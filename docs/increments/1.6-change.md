**Decisions and assumptions** (numbers are CHG-n; the coordinator may add them to `docs/assumptions.md`)
- **CHG-1** One table for PR/ECR/ECN with a type column; tasks in their own table (shared numbering, markings, lifecycle, search, gateway).
- **CHG-2** The resulting revision is created when an object is added to an ECN with `revise` (not at submit or release), so engineers can work on it; a revision label of an abandoned revision is never reused.
- **CHG-3** Marking dominance: an uncovered object is refused by default; the caller may ask to raise the change's markings to the minimal cover (audited, history entry, visible notice, only if the actor and open task assignees keep access). The UI shows the choice as a checkbox next to the picker.
- **CHG-4** Distribution statements order A < B < C < D < E < F by restrictiveness; EAR99 ranks with None; a change in program X may list objects of program X or of no program; export authorizations of a change must be a subset of an export-controlled object's (the minimal cover narrows them, possibly to none).
- **CHG-5** Class I only through a Class I ECR in Approved; a direct ECN is Class II; an ECN takes its ECR's class; a Class II ECR may open an ECN from Draft or Approved; an ECR is classified before submission (optional at creation).
- **CHG-6** Signed content for an ECN = the frozen snapshot text + hash, plus the live content fingerprint of every resulting iteration (description, attributes, document links, BOM lines via participants). The id the engine binds to is derived from (change id, submission number); format versioned as `change-content/1`. Existing part hashes unchanged.
- **CHG-7** While an ECN is under review its resulting revisions are Under Review (locked); rejection or review cancellation returns them to In Work. The part workflow refuses a bound revision with a message naming the ECN number (number only, nothing else).
- **CHG-8** Only a Draft ECN is cancelled (reason code); it abandons resulting revisions (Obsolete through a `change` transition added to the part lifecycle, previous revision latest again, open check-out discarded). Nothing is ever deleted; removal of an affected object is a stamp (`removed_at`). Removing an object whose resulting revision was worked on is refused.
- **CHG-9** A rejected ECR becomes Rejected (can be reworked to Draft or closed); an ECN returns to Draft. Needed a small engine change: the default interface method `CompleteRejectionAsync`, called by `WorkflowService.SignAsync` on rejection (one line in `WorkflowService.Sign.cs`).
- **CHG-10** An ECR becomes Implemented when the last open (Draft or UnderReview) notice created from it is released; a PR is never resolved automatically (manual, with rules).
- **CHG-11** "Open change" = lifecycle state with `is_final = false`. Conflicts exclude the change's ancestors and descendants; `none` (reference) rows do not hold a revision; where-used lists every revision whose latest iteration contains the part, so a revised assembly shows both A and B.
- **CHG-12** Tasks: assignee is a directory user with a work role (not auditor only) who can read the notice (directory snapshot, as A50); the assignee starts and completes (an administrator may complete), anyone with Modify cancels; tasks may be created in Draft, Under Review and Released.
- **CHG-13** ECN number disclosure: an "already held by ECN-x" message names the number only to readers of that ECN.
- **CHG-14** Reason codes are data (`chg.reason_code`, scopes `pr.reject`, `pr.close`, `ecr.close`, `ecn.cancel`).
- **CHG-15** Templates `ecr-ccb-review` (parallel All of 1 to 10 CCB members) and `ecn-release-review` (technical reviewer, then parallel All approvers) are seeded by the migration as ordinary versioned data.
- **CHG-16** Pages that add other objects to the part page compute the banner with `BannerMerge.Union` (parses the banner text formats), because BOM and change panels each report an aggregate banner string.
- **CHG-17** Numbers are system-generated only; explicit numbers (A6, migration) are not offered for change objects yet.
