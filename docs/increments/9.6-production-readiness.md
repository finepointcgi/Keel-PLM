# 9.6 Production readiness: CI, supply chain, packaging, operations proof

Branch `prod-readiness` (from `main` at be9275f), 2026-10-30. No SQL migration. ADR-0059 (CI, SBOM, licences), ADR-0060 (packaging, preflight, backup and restore, upgrade, load). Assumptions A91-A93. Ops guide [ci.md](../ops/ci.md); recorded results in [drill-results](../ops/drill-results/).

## Delivered
- **CI** (`.github/workflows`): `pr.yml` -> `fast.yml` (build `-warnaserror`, unit, integration, OpenAPI drift, links, secrets, workflow lint, licence inventory and policy, advisories, SBOM, Helm and compose bundle checks); `main.yml` adds the browser suite (`e2e.yml`, Chromium cached) and `image.yml` (production image + compose smoke); `nightly.yml` adds `drills.yml`; `axe.yml` runs the accessibility class on pull requests that touch the UI. Actions pinned by SHA, read-only permissions, no `pull_request_target`.
- **Check scripts**: `scripts/ci/check-md-links.py`, `secret-scan.py` (+ `.secret-scan-allowlist`), `lint-workflows.rb`, `dependency-audit.sh`, `scripts/update-openapi.sh --check`; each with a self-test where it is code (link checker, linter, scanner).
- **SBOM and licences**: `keel-sbom` extended (Python add-on with a files digest, development components, `licenses` command with policy and `--check`), `scripts/generate-sbom.sh`, committed generated `THIRD-PARTY-LICENSES.md`, `ThirdPartyLicensesTests` (independent enumeration, mutation tests, policy tests), `docs/review/legal-open-source.md` facts added (status pending).
- **Packaging**: compose bundle limits and healthchecks, `deploy/offline/preflight.sh` run by `install.sh` and `upgrade.sh` (`--preflight-only`, `--skip-preflight`), `versions.json` in the offline bundle, `scripts/verify-packaging.sh` (static properties of the compose file and 13 preflight scenarios), `verify-offline.sh` and `verify-compose-example.sh` extended.
- **`keel-vault verify`** (read-only bulk integrity check of every referenced object), `VaultVerifier`, `VaultReferenceSource.SizeColumn`.
- **Operations proof**: `scripts/ops/backup-restore-drill.sh`, `upgrade-rehearsal.sh`, `load-smoke.sh`, `tests/Keel.LoadTool` (`keel-load`), `tests/Keel.BackupTestTool` extended (documents with files, manifest check, tamper and delete controls).

## Findings the work produced
- **Real documentation bug**: one broken anchor (`docs/ops/integration.md` linked a heading slug that does not exist); fixed. The link checker supports the docs' own `{#id}` heading convention (used in `docs/migration`).
- **Real packaging bugs**: compose rejects `pids_limit` together with `deploy.resources.limits` (limits are written as `deploy.resources.limits.pids`); the app container waited for a vault that had no healthcheck.
- **Out-of-order migration numbers are real**: the previous release (git revision of the 0027 set) did not contain `0026_programs.sql`; it was merged later. The migrator applies by file name, so it ran after the newer files, and the upgrade rehearsal proves the data survives that.
- **Seed rows from forward migrations are real**: `wf.template` gained a row through that migration; the rehearsal therefore checks "no row lost or changed" and requires every gained row to be explained by an INSERT in a new migration, instead of asserting equal counts.
- `scripts/verify-compose-example.sh` was not executable in the working tree (the git mode was); the nightly workflow would have failed on it. The linter and a unit test now check executability.
- `docker start` gives a restarted container a new random host port (the first drill run used the stale port).
- `verify-offline.sh` could not be run in full: it needs the pinned source archives of the LGPL components (`~/.keel-release-sources`, a network fetch that was not done here).

## Decisions (PROD-n)
PROD-1 pipeline on GitHub Actions only, four actions, SHA-pinned. PROD-2 PR gets the fast set; the 19-minute browser suite runs on main and nightly; axe follows UI changes. PROD-3 checks are scripts that run locally. PROD-4 secret scanner is in-repo (no downloaded scanner). PROD-5 licence list is generated, committed, enforced; Python licence ids are catalogue entries. PROD-6 licence policy refuses AGPL, SSPL, BUSL, non-commercial, plain GPL. PROD-7 workflow linter is in-repo, not actionlint. PROD-8 legal status stays pending. PROD-9 compose file keeps its name; limits are starting values. PROD-10 preflight runs before anything is loaded; warnings do not stop. PROD-11 FIPS host required unless explicitly waived. PROD-12 `versions.json` is signed with the bundle. PROD-13 Kubernetes preflight is tools, cluster and values only. PROD-14 `keel-vault verify` reads every byte and is read-only. PROD-15 drills use unique `keel-drill-*` names and clean up only their own. PROD-16 the vault backup in the drill is a cold volume copy. PROD-17 the upgrade rehearsal reads the previous set from git history. PROD-18 "gained rows" must be explained by a migration INSERT. PROD-19 the load smoke uses an in-repo client and the shipped limits for every service. PROD-20 recorded results are committed as measured and a failed run must not be committed (a unit test checks).
