# Increment 1.7 (packaging half): containers, compose, Helm, offline bundle, ops docs

Seed data, E2E and the demo script are the other half of 1.7 and are not described here. Decisions: ADR-0020.

## Delivered
- `Dockerfile`, `.dockerignore`, `deploy/images.env` (digest pins): UBI 9 .NET 10 SDK and ASP.NET images, non-root, read-only-root friendly, `--migrate` and `keel-audit` entrypoints in one image, OCI labels, `HEALTHCHECK`.
- `deploy/compose/compose.prod-example.yaml` + `prod-example/` (Caddy, nginx alternative, TLS/secrets generators, postgres entrypoint, test overlay with stub IdP).
- `deploy/helm/keel` chart (+ `values.schema.json`, `values-dev.yaml`, `ci/production-values.yaml`).
- `deploy/offline/*` (verify, install, upgrade, lib) and `scripts/package-offline.sh`, `verify-offline.sh`, `verify-helm.sh`, `verify-compose-example.sh`, `backup-restore-test.sh`, `refresh-image-pins.sh`.
- `docs/ops/`: configuration, compose-example, kubernetes, offline-install, hardening, backup-restore, disaster-recovery, upgrade, nist-800-171-mapping.
- Application changes required by packaging: `KEEL_SECRETS_DIR` key-per-file secrets; `Keel:DataProtection:KeyDirectory`; `Keel:Proxy:*` forwarded headers; `--healthcheck`; clean exit on fatal startup errors; vault request timeout (`Keel:Vault:RequestTimeoutSeconds`, `VaultUnavailableException`, 503 + Retry-After) which closes the known "upload hangs when the vault cannot write" gap.
- Tests: `VaultTimeoutTests` (4), `PackagingConfigurationTests` (5); tool project `tests/Keel.BackupTestTool` for the backup test.

## What was run
- Unit and integration suites, build with `-warnaserror` (results in the session report).
- `verify-compose-example.sh`: 18 of 18 checks passed against the real compose example, **using a substitute app image** (the repository Dockerfile, with the runtime stage on `mcr.microsoft.com/dotnet/aspnet:10.0-noble` and the publish output of this tree injected through `--build-context publish=...`), because the Docker VM had under 500 MB free.
- `backup-restore-test.sh`: 8 of 8 checks passed (see backup-restore.md).
- `verify-helm.sh`: all checks passed (helm 4.3.1, kubeconform 0.6.7, Kubernetes 1.30 schemas; the ServiceMonitor CRD schema was skipped).
- `package-offline.sh` and `verify-offline.sh` against a bundle that contained the substitute image tagged `keel/api:1.7.0`, the three pinned third-party images, the chart, SBOMs.
- Shellcheck (warning level) on all new scripts.

## What was only written (not executed)
- The UBI image build (SDK image about 1 GB, runtime layers about 100 MB compressed; the Docker VM had 250-480 MB free). Verified instead: the pinned digests resolve, the ASP.NET image repository name (`dotnet-100-aspnet`), its contents (bash, curl, microdnf present: hence the hardening step) and `dotnet publish` output on the host with the same commands. Unverified: that the RH SDK 10.0.113 compiles the tree (global.json pins 10.0.402, so the Dockerfile ignores it).
- The FIPS-enabled path: the Docker VM kernel has no FIPS flag and `/proc/sys/crypto/fips_enabled` cannot be bind-mounted there. Verified: disabled gives Degraded readiness and `RequireFips=true` exits 1.
- `install.sh --k8s`, `upgrade.sh` real runs, Helm install on a cluster (none was used), the nginx proxy variant, image SBOMs (syft absent), podman/ctr loading.
- `install.sh --compose --no-start` was executed by `verify-offline.sh`; a full start from the bundle was not (the same stack was started by `verify-compose-example.sh`).

## Findings for the coordinator
- `deploy/compose/compose.yaml` (dev) runs SeaweedFS without `-master.telemetry=false`; the dev store reports statistics to telemetry.seaweedfs.com by default. Not changed (outside scope); the production example disables it.
- The runtime default on an unhandled startup exception was an abort with a core dump that spun a CPU for over a minute; fixed with an exit-1 handler.
- Data Protection keys are written unencrypted; the volume must be encrypted (documented).
- Idle-session lock (3.1.10), malware scanning, vault GC and SIEM forwarding remain open (nist-800-171-mapping.md).
