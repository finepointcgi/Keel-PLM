# Increment 5.0: closing the compliance gaps

Closes the four gaps recorded in `docs/ops/nist-800-171-mapping.md`: idle session lock (3.1.10, 3.1.11), malware scanning of uploads (3.14.2), vault garbage collection,
SIEM forwarding (3.3.x, A20). Design and rationale: [ADR-0026](../adr/0026-session-lock-scanning-gc-siem.md). Operator runbook: [compliance-features.md](../ops/compliance-features.md),
[siem-onboarding.md](../ops/siem-onboarding.md).

## Assumptions and decisions (CMP-n)
- **CMP-1** Idle clock per sign-in (session id claim), shared by all tabs; activity in any tab counts. Warning default 60 s; defaults 15/15 minutes.
- **CMP-2** Lock audit vocabulary: `session.lock` (idle|manual), `session.unlock` (step-up), `session.lock_expired` (grace passed) then `session.terminated_idle`. Sessions are referenced in audit by a hash prefix, not the id.
- **CMP-3** Unlock keeps the route but **not unsaved form input**: the page is destroyed while locked and re-read after re-authentication. Keeping input would hold marked data in memory beneath the lock.
- **CMP-4** The registry is in memory (single node / sticky sessions). A restart or another replica starts sessions active with a fresh idle clock. A database-backed registry is judged necessary for multi-replica production and is Phase 5. Cookies from before the lock have no session id and are refused (one re-login).
- **CMP-5** Quarantine is per **document + content hash**, not per `document_file` row or vault object: check-in copies file rows, and another document sharing the object may be clean.
- **CMP-6** Scan results are recorded per content hash (append-only log) and exposed per file row through a view; `unscanned` is the status of anything with no clean record.
- **CMP-7** Garbage collection deletes only from the CLI or the configured service, never from the UI (a dry-run button only). Delete via CLI also needs `--confirm-bucket`.
- **CMP-8** Pending-upload marker lease is 2 hours; GC grace minimum is 1 day (default 7); the cap counts candidates in dry run too, so previews equal deletions.
- **CMP-9** SIEM delivery is at least once to the TCP stack: TCP has no acknowledgement. The sender drops connections the peer closed and checks after each write; residual loss is detected by the SIEM's continuity check, and replay is a documented cursor rewind.
- **CMP-10** The forwarder sends only identifiers, actions, outcomes and the chain hashes; the payload (names, markings, details, actor attributes) is never forwarded, so the SIEM cannot recompute hashes: the forwarder does and alerts (`siem.chain_break`).
- **CMP-11** A persisted chain break keeps health Degraded until a database owner clears it by SQL (documented); health is never Unhealthy so an SIEM outage cannot take the application out of service.
- **CMP-12** The enterprise number in `keel@PEN` is the IANA documentation placeholder 32473 until the organization supplies its own.
- **CMP-13** `Disabled` scanning stays the code default (tests, tools, dev) but is refused under `RequireFips` without the acknowledgement; this changes startup for production images, the compose example and the chart (they now need scanning settings or the acknowledgement).
- **CMP-14** Content-hash columns of tables from other increments must be classified in `VaultReferences` (a schema test fails otherwise). The coordinator must classify columns added by EBOM/MBOM (0011) and Integrations (0012) when merging.
