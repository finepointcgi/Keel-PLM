# Gap wave D: accessibility audit and performance at scale (increment 7.7)

Design: [ADR-0034](../adr/0034-accessibility-and-performance-at-scale.md). No migration (0018 stays free). Docs: [ux/accessibility.md](../ux/accessibility.md), [ops/performance.md](../ops/performance.md).

## Delivered
- Automated accessibility audit (`tests/Keel.E2E/AccessibilityTests.cs`) with a vendored axe-core 4.10.2 (`tests/Keel.E2E/vendor/axe-core/`, `VENDOR.md`: version, SHA-256, licence), over every major page and tab, the visuals in both views,
  the viewer, admin, and overlays, in light, dark, high-contrast (1280 px) and light and high-contrast (375 px). No allow-list.
- Violations found and fixed (first run): 114 page states failed. By rule: `region` (marking banners were `role="note"`, now `role="region"`; the viewer toolbar sat outside `main`), `aria-required-children` (critical; treegrid and grid bodies
  now `role="rowgroup"`), `color-contrast` (serious; `table.data a` overrode `a.button`: 1.15:1), `empty-table-header` (change affected objects, change tasks, reconciliation), `landmark-complementary-is-top-level` (impact map and treemap detail panes),
  `landmark-unique` (timeline groups), `button-name` and `link-name` at 375 px in high contrast (brand text and user name were `display:none`; now visually hidden), `scrollable-region-focusable` (wide tables at 375 px; `shell.js` makes
  a scrolling wrapper without focusable content a labelled focusable group; the virtualized grid body is focusable). Contrast of every theme token pair was already clean.
- Performance: `ScalePerformanceTests` (about 108,000 parts incl. a 50,000-line structure, 50,000 documents, 20,000 changes, 150,000 audit events, 20,000 notifications; `KEEL_SCALE_FACTOR=3` for 250,000 parts) with budgets, plans and a report file;
  `ScaleTests` (E2E) with a 50,000-line structure in its own database and host (`E2EFixture.EnsureScaleHostAsync`).
- UI paging where every row was DOM: where-used, purchasing summary, comparison tables (100 rows per page); the structure-difference picture caps at 500 lines with a notice.
- Bug fix: home card "Changes in my programs" now filters by program in the query (`ChangeSearchQuery.Programs`), not over the newest 200 readable open changes.

## Assumptions
- GAP-D-1: No index migration. EXPLAIN shows every list is one pass over the access-filtered set (needed for `count(*) OVER ()`); at 108,000 parts a list costs 60 to 100 ms and at 250,000 under 300 ms, and a sort-key index cannot remove the pass. GAP-A-5 is closed by measurement; re-measure before adding any index.
- GAP-D-2: axe-core is MPL-2.0, not MIT as the brief assumed. It is vendored unmodified under tests/, never shipped, never referenced from src/; tests pin the hash and assert it is not in `src/` or the image build. MPL-2.0 is file-level, so no obligation attaches to the product.
- GAP-D-3: The page banner of a paged table (where-used) stays the aggregate of the whole result, not of the page shown: a deliberate over-marking (never under-marking) so the banner does not change while paging. The difference picture's 500-line cap likewise keeps the banner of the whole comparison.
- GAP-D-4: The audit uses the `best-practice` axe tag as well as WCAG A/AA, so landmark, region and header rules fail the build although they are not strictly WCAG failures. Chosen because the brief names landmarks.
- GAP-D-5: Marking banners became `role="region"` landmarks (was `note`) so no content is outside a landmark. Screen readers announce "Marking banner (top), region" followed by the text; the visible banner is unchanged.
- GAP-D-6: A focusable scrolling group is added dynamically by `shell.js` (only when a wrapper overflows and has nothing focusable). It runs after the circuit starts; the first ~60 ms of a page have no such tab stop.
- GAP-D-7: Performance budgets are medians of five calls at several times the measured values on a laptop; on much slower disks or loaded VMs raise `Budget` rather than retrying. The numbers are for one user session, not concurrent load (no load test was run).
- GAP-D-8: The scale host is a third process on its own database in the E2E container; its Keycloak redirect URIs are added at fixture start. Ordinary tests never see the 50,000-line data.
- GAP-D-9: Manual accessibility items (screen reader pass, zoom 200/400 %, forced colours, 3D viewer) remain open and listed in docs/ux/accessibility.md. This is not a signed VPAT.

## Tests
Unit: 896 passing (banner role assertions updated). Integration: 585 passing (new: `ScalePerformanceTests`, 2). E2E: 61 passing (new: `AccessibilityTests` 7 = hash pin, not-shipped, five audits; `ScaleTests` 1).

- Test-infrastructure fix: lock state is shared through the database, so the short-idle-lock host also ended idle sessions of tests on the main host (step-up waits, long audits) whenever a lock test had run earlier in the order. `BrowserSession.SignInAsync` now stops the lock host (`E2EFixture.StopLockHostAsync`) before signing in anywhere else; the next lock test restarts it.

## Not built
Virtualization of the structure-difference picture (capped instead); a formal VPAT; concurrent-load testing; hosted browser matrix beyond Chromium.
