## Assumptions (INT-n)
- INT-1 Event types are dotted lower case with an integer version; additive payload changes keep the version, consumers ignore unknown fields. `mbom.released` is added later by a constant, a schema and an emission point.
- INT-2 Ordering: per aggregate within a sink, by outbox sequence; none globally. A failed event blocks later events of its aggregate until it succeeds or dies.
- INT-3 Deliveries are created with the event for sinks enabled at that moment; a later sink gets no history (use the pull API). Clearance is evaluated at dispatch.
- INT-4 Readers see an event only when its transaction is older than all in-flight ones; cursors are `(xid, seq)`. A long-open transaction delays events.
- INT-5 At-least-once with a 2-minute lease; shutdown releases the lease without counting an attempt.
- INT-6 DoDI 5230.24 table as in the ADR; a foreign recipient is cleared for B to E only through an authorization listed on the object and held by the recipient. Needs confirmation by the export compliance office.
- INT-7 `bom.published` uses placeholders (not whole-event withholding) for lines the assembly's markings do not cover; oversized full structures are skipped and audited.
- INT-8 `bom.published` is emitted when the assembly revision is released. A later release of a child does not re-publish its parents; ERPs reconcile with the pull API.
- INT-9 Webhooks: https only, host or CIDR allow-list (default deny), dangerous addresses refused (dev switch exists), no proxy, no redirects.
- INT-10 Secrets by name from `Keel__Integration__Secrets__{name}`; client certificates (PEM with key) and CA bundles by name from path settings.
- INT-11 Response rules: 2xx delivered; 408, 429, 5xx, network errors and timeouts retry; 3xx and every other 4xx (including 410) are permanent.
- INT-12 TDP element categories follow MIL-STD-31000 as understood by the team; the standard text was not available offline. The mapping is admin-editable and should be reviewed against the standard.
- INT-13 A part TDP contains the root and every part of its LatestReleased structure and the documents linked to each (per A23); a baseline TDP uses the frozen items and the documents pinned at creation (create the baseline with documents). Only established or superseded baselines are exported.
- INT-14 A TDP with unresolved lines, unreadable objects, more than `TdpMaxParts` parts or `TdpMaxDocuments` documents is refused.
- INT-15 The record and audit event commit before the manifest is released; a failure after that leaves a record without a delivered package.
- INT-16 Export is a POST that streams the ZIP (UI: form POST with antiforgery) instead of POST-then-GET; `GET /tdp/{id}/verify` checks the record, `POST /tdp/{id}/verify` checks an uploaded package.
- INT-17 `plm-integration`: Read only, not in `Roles.All`; pull API policy only.
- INT-18 Administrator state overrides emit events (`via: admin`); the migration importer's bulk loads do not (use the pull API for the initial load).
- INT-19 OpenAPI documents only the integration surface.
- INT-20 A small JSON Schema validator was written for tests (air-gapped supply chain); it has its own tests.
- INT-21 The outbox is never purged here; retention is Phase 5.
- INT-22 Documents have no review workflow gateway yet, so `document.released` fires on administrator override only.
- INT-23 A TDP combining two programs cannot be marked as one package and is refused.

## Tests
Unit and integration counts are in the hand-off report.
