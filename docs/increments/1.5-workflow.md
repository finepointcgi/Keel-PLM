### 1.5 Review workflow, e-signature and release (2026-10-27)

**Delivered**
- Migration `0006_workflow.sql`: schemas `identity` and `wf`; `identity.user_directory`; versioned templates, signature meanings (`wf.reason_code`), instances, tokens, tasks, immutable signatures and history; seeded template `part-release-review` (serial technical review by one reviewer, then parallel approval with rule All, then release); In Work ⇄ Under Review are now `workflow` transitions.
- `Keel.Workflow`: pure engine (`WorkflowEngine`: Task, Parallel with All/Any/N-of-M and short circuit, Serial, End), template parser/validator, `WorkflowService` (start, sign, cancel, reassign, inbox, task/instance/object views, admin list, templates list/upload, directory search, signature verification), `UserDirectory` (upsert at UI sign-in, throttled touch on API calls), `SignDraftStore`, `StepUp`, canonical-JSON SHA-256 signature hashing.

**Decisions and assumptions** (numbers are high to avoid colliding with the Documents/BOM agents; the coordinator should add the rows to `docs/assumptions.md` and may renumber)
- **A50** Participant eligibility is evaluated from the directory snapshot (last sign-in or API call) when picked, and again against the live token when signing. A role change at the IdP is enforced at signing, not at assignment.
- **A51** Separation of duties: the submitter cannot be a participant, cannot sign, and an administrator cannot reassign a task to them.
- `plm-viewer` as a required role means viewer or any higher role; auditors never review or sign.
- Any rejection returns the part to In Work with the seeded rule All; with Any / N-of-M a rejection only decides once the required approvals become unreachable. Undecided tasks are skipped.
- Entering and leaving Under Review is workflow-only (lifecycle data change). The admin "set state" override still works; a workflow orphaned by it cannot be signed (conflict) and is closed with Cancel.
- The signature hash additionally binds signer, decision and comment; markings are hashed from the snapshot stored on the signature.
- Real Keycloak password-grant (direct access) tokens carry no `auth_time`, so the dev CLI cannot sign over REST; authorization-code tokens (UI, real API clients) do. The dev realm was not changed.
- Step-up keeps the original absolute session lifetime.
- The in-memory sign draft needs sticky sessions (already required by ADR-0014).

**Tests that I changed in existing files:** `PartServiceTests` (manual submit is now refused; override used for the lock test), `PartApiTests` (manual submit returns 409), `ApiFactory.Token` (auth_time, display name), `PostgresFixture` (Postgres data on tmpfs: the Docker VM disk was 99% full and the suite ran it out of space), `ArchitectureTests` (Workflow module rule, `wf.instance` filter rule).
