# 9.6 Localization foundation (2026-10-30)

ADR-0057, migration 0036, assumptions A85-A87. Branch `i18n-foundation`.

## Delivered
- **Per-user language**: `ws.preference.language` (migration 0036, default `'en'`, CHECK on the tag's shape only). `UserPreferences.Language`, `ShellState.SetLanguageAsync`, `<html lang>` from the stored value. (LOC-1)
- **Language picker** in the user menu (native names, `lang` on each choice, `aria-pressed`, keyboard operable). Choosing saves and reloads so the new circuit starts in the language. (LOC-2)
- **Resource infrastructure**: `Resources/ShellStrings|CommonStrings|PageStrings` (`.resx` + `.es.resx`, satellite assembly), `KeelLocalizer<T>` (an `IStringLocalizer<T>` over `ResourceManager` reading the circuit's `UiLanguage`), `Locales` (the shipped list), `Loc` (English fallback for the small shared controls when localization is not registered). (LOC-3)
- **Culture-aware display** without ICU: `UiLanguage.Utc/Date/LongDate/Number/Quantity/Unit`; separators, date patterns, month/day names and unit symbols are `Format.*` and `Unit.*` resources. The thread culture stays invariant. (LOC-4..6)
- **Pseudo-locale** `qps-ploc`, generated (accents, +~33 % length, brackets, placeholders kept), offered only when `Keel:Localization:PseudoLocale=true`. (LOC-3)
- **Spanish (`es`)**: complete for every converted string (469 keys across the three files; parity enforced by test).
- **Converted (all strings of these)**: skip link, top bar, error banner, navigation rail (groups and links, 52 labels), user menu, command palette (placeholder, hints, results groups, 31 commands, kinds, states); Home and its cards (Attention, Recently viewed, Favorites, Programs, Released, Quick actions; the other cards are not converted); Parts list, quick create form (`QuickPartForm`), part page action bar, tabs, header badges, dialogs and toasts of edit/save/check-out; Documents list and create; My tasks, task (approval/review) page and sign panel; shared table, pager, skeleton, confirmation dialog, breadcrumbs; not-found and access-denied pages; the reason texts (`UiText.Reason`, `WorkflowText.Reason`, `Due`) of those flows.
- **Banners and classification text are untouched** (LOC-7): no localizer in `MarkingBanner`/`MarkingChip`, no marking words in any resource value, the E2E test compares the English and Spanish banner text character for character.

- E2E (`LocalizationE2ETests`, 3; `KEEL_E2E=1`): Spanish through Parts list/create (quick add in Spanish creates the part), Documents, Tasks, Home, palette, reload and a new sign-in keep the language, banners identical; axe audit of 6 converted pages + user menu + palette in `es` and the pseudo-locale at 1280 and 375 px plus a no-sideways-scroll check; keyboard operation of the picker.

## Decisions
- The language is held by a scoped `UiLanguage`, not the thread culture (A86): nothing that parses, exports, hashes or stores can change with the language.
- `PredefinedCulturesOnly=false` is added to `Directory.Build.props` beside `InvariantGlobalization`, because `new CultureInfo("es")` needs it without ICU. Only shipped tags are created.
- The data-driven labels (navigation, palette) keep English as the identity (Simple view, open/closed groups, routes, test ids) and translate only the shown text.

## Adding a language (translation only)
1. Copy `Resources/ShellStrings.es.resx`, `CommonStrings.es.resx` and `PageStrings.es.resx` to `*.<tag>.resx` and translate every value (keep `{0}`-style placeholders; translate the whole sentence). In `CommonStrings` also set the `Format.*` keys (separators, date pattern, month and day names, first day of the week) and the `Unit.*` symbols.
2. Add `new("<tag>", "<name in that language>")` to `Locales.Shipped`.
3. Run the unit tests: `LocalizationTests` fails with the list of missing keys, orphan keys, changed placeholders or empty values until the files are complete.
Languages with more than two plural forms or with right-to-left text need more than this (see below).

## Not done / known limits
- **Not converted** (English in every language): every page not listed above (Changes, Baselines, BOM editor, MBOM, Quality, Sourcing, Requirements, Compliance, Records, Programs, Output, Administration, Migration, Integration, Viewer, Compare, Access check, Audit log, Profile, Style guide, the portal, the lock panel and session-warning text), the other Home cards (Watched activity, Records, Quality, My program work, Compliance), the dialogs not listed (add document, upload version), search results page, notification bell and activity text, and the `aria-label`s of the marking banner landmarks.
- Text produced by modules and services (validation messages, workflow event details, attention-card detail lines, search hit state labels not in the resources) stays English; administrator-defined labels (lists, lifecycles, attributes, classification) stay as stored (A87).
- Dates are UTC; there is no per-user time zone. Numbers use thousands grouping only. Plural rule is one/other. No regional variants (es-MX uses `es`).
- Browser `Accept-Language` is not used to pick a first language (A85); a new user starts in English.
- Reports, release packages, TDPs, CSV/Excel exports and e-mails are not localized (they keep their stored format and English wording).
- **Right-to-left** is out of scope. Layout issues to expect: the rail and the banner use physical `left`/`right` and `margin-left` in `layout.css`/`components.css` (should become logical properties), icons with direction (chevrons, sort arrows, back arrows) are not mirrored, `text-align: left` on tables and the command palette, the kbd hints and Gantt/timeline visuals assume left-to-right time, and `dir` is fixed at `ltr` in `App.razor`.
- The spec's rule "no concatenation" is enforced for the converted files only; unconverted files still build some sentences from pieces (for example `result.Total part@(... "s")` patterns in other pages) and will need the same treatment when converted.
