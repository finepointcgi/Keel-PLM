# 9.1 UI polish (ADR-0046)

Visual pass over the whole Blazor UI, no behaviour, access rule, marking or banner change. No migration, no C# service change.

## Delivered
- Tokens: calmer palette in light, dark and high contrast; accent tint, radii, elevation, durations, type tweaks (`tokens.css`).
- Shell: brand tile, softer top bar, rail with tinted active item, breadcrumbs; object header with accent rule; sticky action bar.
- Controls: button hierarchy, inputs with hover/focus/invalid states, 3 px focus ring with halo.
- Surfaces: cards with icon tile and KPI-style counts, panels, tables (sticky header, zebra, hover), tabs, stepper, chips (shield icon), state badges (dot), toasts, dialogs,
  notification flyout, palette selection, empty states, notices and validation boxes.
- `/tools/style-guide` page and `styleguide.css`; Tools nav entry; included in the axe audit list.
- Tests: contrast pairs for the accent tint and status colours on surface-2, theme-scope equality, `styleguide.css` in the colour-literal test, `PolishTests` (style guide in every theme with banners; screenshots on request).
- Screenshots: `docs/ux/screenshots/polish-before-*.png` (light) and `polish-after-*.png` (light and dark, phone, style guide).

## Decisions
- UI-1 Tokens only; new tokens are listed in ADR-0046. UI-2 Keep class names; add classes instead of renaming. UI-3 State badges get a CSS dot (no markup change).
- UI-4 Marking chips gain an icon (`MarkingChip.razor`), text unchanged. UI-5 Zebra rows use `color-mix` of two tokens (no literals).
- UI-6 The style guide shows other themes with scoped token copies; a unit test prevents drift. UI-7 Banners, `.demo-banner`, `--banner-*` untouched.
- UI-8 No existing test selector changed; one entry added to the axe page list.

## Not done / deferred
- Bespoke per-family redesigns beyond what the shared classes give (page markup was not touched, to avoid conflicts with the concurrent model-versioning work).
- Diagrams (impact map, treemap, Gantt, timelines) inherit the new tokens; their layouts and legends are unchanged.
- Dark "before" screenshots were not kept (the first capture run did not apply the theme).

## Full-suite repair after the MudBlazor rail landed (2026-10-29)
The full browser suite failed 8 of 106 tests on main. One root cause, several symptoms. The polish branch itself was fine (a clean checkout of the commit before the rail change passed all 103 tests, including the five axe audits).
- A docs commit (6f32dde) carried a half-finished shell change: `RailNav` rebuilt on MudBlazor nav links with collapsible groups, rail rules removed from `layout.css`, and `App.razor` linking `MudBlazor.min.css` after the Keel styles plus a `mud-keel.css` that is not in the repository.
- Axe (all five audits, product fix): MudBlazor's element rules `a { text-decoration: none }` and `a { color }` came later in the cascade than `base.css`, so in-text and in-table links lost their underline (`link-in-text-block`). MudBlazor's stylesheet is now linked first so the design system wins; the dangling `mud-keel.css` link is removed. The audit is unchanged.
- Rail styling (product fix): the removed rules are restored for the new markup (group header, `.rail .rail-link > a`, collapsed and phone variants), tokens only.
- Records, Administration and Tab-order tests (test fix): rail groups are disclosure buttons and a closed group renders no links. `BrowserSession.RailLinkAsync` opens the group first; the Tab test presses Enter on a closed group header, as a keyboard user does, with a budget of 160 presses. The negative role checks now also assert the group itself is absent, so the role gate is still proven.
- Open-group state lives in the circuit (it survives navigation, not a reload). Persisting it per user needs a column in the `ws` preferences table (a migration); deferred.
- Merge note: the main checkout has uncommitted `mud-keel.css` and `m3.css` work that was not touched. Keep MudBlazor before the Keel styles in `App.razor`.
