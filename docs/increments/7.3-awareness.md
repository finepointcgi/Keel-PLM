## Assumptions
- AWR-1: A notification row stores a reference id (comment id or task id) in addition to kind, object pointer and actor, so a link can land on the comment or task. It is an opaque id, never marked data.
- AWR-2: Rows whose object the viewer can no longer read count once in the unread badge and show as neutral rows under All and Unread only; kind tabs omit them (a kind tab would reveal the kind).
- AWR-3: Review requests (kind review) and approval tasks (kind approval) are different notification kinds; both cannot be turned off, with change tasks and mentions.
- AWR-4: "Watched object changed" is a new checked-in version; state changes other than Released and Obsolete come from the owning transaction, Released, Obsolete, approvals, baselines and MBOMs from the outbox, so each event notifies once. Changes, baselines and MBOMs have no check-in hook (only their outbox events and the review and change hooks notify).
- AWR-5: "Authored" is covered by auto-watch (create) and by replies: the author of the replied-to comment is told. Watchers at level "decisions" get decision kinds only (not comments, versions or plain state changes).
- AWR-6: Commenting needs viewer, author, approver or administrator; auditors and service accounts read only, so audit independence is kept.
- AWR-7: Comment text references show only the object number as a link chip (no name or markings), so the page banner needs no extra aggregate; unreadable numbers stay plain text.
- AWR-8: Viewing the activity feed or comments is not audited for ordinary viewers (viewing the object is); a denial is audited (`activity.read`, `comment.read`, `watch.set`), and an auditor's switch to include views writes one `activity.read` event.
- AWR-9: The mention list follows the trailing `@token` of the text (no caret tracking); logins are matched case-insensitively against the directory.
- AWR-10: The activity feed omits events of OTHER objects that reference this one (an ECN adding this part, a baseline containing it). The audit table has no index on the referenced object; adding one or a reference table is a follow-up.
- AWR-11: Notifications use no DataTable (a grouped, selectable list fits better); the watch list is a plain table.
- AWR-12: No REST API and no OpenAPI entries were added: the features are UI features.
