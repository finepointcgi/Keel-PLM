# 1.3 Documents and vault (2026-10-27)

## Backend

### Delivered
- **Vault** (ADR-0015): `Keel.Documents.Vault.ObjectVault` over the S3 API (AWSSDK.S3, path style, explicit credentials,
  SDK checksums off so no MD5/CRC is computed). Objects are keyed by the lowercase hex SHA-256 of their bytes, hashed while
  streaming (one part in memory; small files go straight to their key, large files multipart to `staging/` then server-side
  copy). Size, media type and SHA-256 are stored in the database and re-verified on every download. Optional SSE-S3.
  Configurable `Keel:Vault:*`, default max upload 2 GiB. Readiness check `vault`.
- **Dev/test store:** SeaweedFS 4.47 (`weed mini`, Apache-2.0) in `deploy/compose/compose.yaml` on `127.0.0.1:18333`
  with a dev-only identity file; the integration tests run the same image via Testcontainers.
- **Migration `0003_documents.sql`:** lifecycle `document-default` (same states/transitions as parts); document
  master/revision/iteration (`D-nnnnnn`, ASME Y14.35 via `Keel.Core.RevisionScheme`); `document_file` (iteration files,
  one primary + attachments, immutable); `document_checkout` + `document_checkout_file` (private working copy). Same DB
  guards as parts: immutable iterations and files, nothing written to locked revisions, no deletes, identity immutable.
- **Migration `0004_part_document_links.sql`** (ADR-0016): `part_document_link` owned by part iterations (immutable,
  describes ⇔ pinned revision, composite FK to the revision of the same document) and `part_checkout_document_link`
  (working copy, cascades with the check-out).
- **`Keel.Documents.DocumentService`** (references Core, Security, Audit only): create (optional initial primary file),
  get (404 + audited denial), search (FTS/trigram, read filter, aggregate banner, type/state filters), check-out (copies
  the latest iteration's file list), working-copy description, upload (primary replaces primary; names unique
  case-insensitively), remove file, check-in (copies working files; bytes are not copied), undo (owner or admin), manual
  transitions, admin set-state with reason, markings change with reason. Access and check-out are checked **before** any
  byte is accepted and again under the master row lock.
- **Marked download** (A10): `DownloadAsync` requires Download, audits `document.download` (file, file id, SHA-256,
  iteration, banner, format) and denials (404 for unreadable). PDFs are stamped in place with PDFsharp 6.2.4: each page is
  normalized (rotation, origin), enlarged by a header band (banner) and footer band (banner, CUI designation, export
  classification, DoDI 5230.24 distribution statement, DoDD 5230.25 export warning, destruction notice, trace line), the
  original content clipped to its old box and annotations moved with it. Other formats (and PDFs that cannot be parsed or
  exceed `MaxPdfStampBytes`) come as a ZIP: `MARKINGS.pdf` cover sheet, `MARKINGS.txt`, original file (stored, unchanged).
  Fonts: DejaVu Sans embedded as resources with its licence; no system fonts needed.
- **Links** (ADR-0016): add/remove links in the part's working copy (caller must hold the part check-out; Read on the
  document; hidden documents answer "not found"), per-iteration listing with working links for the owner and
  `newerRevisionAvailable`, reverse listing (parts whose latest iteration links to a document). Inaccessible documents or
  parts are redacted placeholders produced in SQL. `PartService` check-out/check-in/undo carry links forward (plain SQL,
  delimited helper `CopyDocumentLinksAsync`).
- **API** (`DocumentEndpoints.cs`, registration in `Infrastructure/DocumentsSetup.cs`; Program.cs got two lines):
  `/api/v1/documents` GET/POST (multipart: `metadata` JSON then optional `file`), `/{number}` GET, `/checkout`,
  `/working-copy` PUT, `/working-copy/files` POST (multipart: `role` then `file`), `/working-copy/files/{fileId}` DELETE,
  `/checkin`, `/undo-checkout`, `/state`, `/markings`, `/{number}/files/{fileId}/download` (header `X-Keel-Markings`),
  `/{number}/parts`; `/api/v1/parts/{number}/documents` GET (`?revision=&iteration=`),
  `/api/v1/parts/{number}/working-copy/documents` POST, `/…/{linkId}` DELETE; `/api/v1/metadata/documents`.
- `RevisionScheme` and `Lifecycle` moved from Keel.Parts to Keel.Core (Lifecycle loads through plain ADO.NET).

### Decisions
- Store: SeaweedFS `weed mini` for dev/test (licence, single container, SigV4 + multipart + copy + SSE-S3 verified by tests).
- Content key is the bare SHA-256 hex; uploads that fail after reaching the vault leave a harmless orphan (GC is Phase 5).
- Integrity failure: HTTP 500 "Stored file failed integrity verification", audited as `Failure`, nothing delivered.
  Large non-PDF downloads verify in a full pass first, then again while streaming (mismatch aborts the transfer).
- `X-Keel-Markings` is ASCII: non-ASCII characters and `%` are percent-encoded UTF-8 (`·` → `%C2%B7`).
- Multipart is parsed section by section and streamed into the vault (no `IFormFile`, no temp files, so antiforgery is not
  involved); text fields must precede the file. The request size limit is raised per request to `MaxUploadBytes` + 1 MiB.
- PDFs are detected by magic bytes; stamping enlarges pages instead of overprinting. PDFs that cannot be opened
  (encrypted, damaged) fall back to the marked ZIP and the reason is audited (`stampError`).
- ZIP entries are stored, not deflated.
- Submitting a document for review requires a primary file; a check-in cannot drop an existing primary (A24).
- Removing a link to a document the caller cannot read is refused with the generic reason `document.read_denied`.
- Test fixtures keep PostgreSQL and SeaweedFS data on tmpfs (the Docker disk on the build host was 99 % full).
- PDFsharp's transitive `System.Security.Cryptography.Pkcs` 8.0.1 has advisories; pinned to 10.0.14.
- New assumptions A22 (no determination date yet), A23 (`references` resolution), A24 (primary file rule).
