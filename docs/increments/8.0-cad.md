## Assumptions
- **FEAT-CAD-1** A package is a set of documents; the CAD role (model, drawing, derived-pdf, step) belongs to the document, not to the file. Derived outputs are separate documents that reference their model.
- **FEAT-CAD-2** The connector declares dependencies; Keel never reads native CAD files. Stale means "the referenced document's latest iteration differs from the one recorded".
- **FEAT-CAD-3** Check-in creates one iteration of every member; `skipUnchanged` is opt-in. Undone new documents stay as empty A.1 documents (documents are never deleted).
- **FEAT-CAD-4** Connectors receive the unchanged-file ZIP (cover sheet and `MARKINGS.txt` alongside), not a stamped PDF, so bytes round-trip.
- **FEAT-CAD-5** A hidden related document is counted, never named (as BOM placeholders, A4); a package with hidden members needs `allowPartial`.
- **FEAT-CAD-6** A proposal carries markings chosen by its creator (who must be allowed Modify under them); applying needs Modify on those markings. Created parts take the proposal's markings.
- **FEAT-CAD-7** STEP: quantity is the count of occurrences; explicit quantity entities, placements and complex instances are not read. Part number is `PRODUCT.id`.
- **FEAT-CAD-8** Removals are off by default; a proposal never removes BOM lines unless `applyRemovals` is set. Released parents are never revised by apply.
- **FEAT-CAD-9** Attribute matching (`matchOn`) compares text equality with the latest iteration's attribute value; at most 2,000 attribute lookups per proposal.
- **FEAT-CAD-10** Sets are limited to 500 documents, proposals to 20,000 parts and 100,000 lines, files to 64 MiB for structure files.
- **FEAT-CAD-11** Set check-outs have no timeout; the owner or an administrator undoes them.

## Verification on the real stack (2026-10-29, after Docker was restored)
Run against Testcontainers and the E2E stack (merged with main, sourcing and variants):
- `CadApiTests` 4/4, `CadServiceTests` 1/1, `CadTests` (E2E) 3/3, the axe pages for the CAD tab, the proposals list and the review page pass.
- Two test expectations were wrong; the product was right:
  - The model in the package round trip is created as iteration 1 and had never been checked in, so the set check-in makes it iteration 2 (the test said 3). No behaviour change; `skipUnchanged` remains opt-in (FEAT-CAD-3).
  - The hidden-versus-missing 404 bodies differ only in the problem-details `traceId`, which is per request. The test now removes `traceId` and requires every other member (status, type, title, detail, instance) to be identical.
  - A third mistake in the same test: it declared a reference to the ITAR document as the "unknown reference" case, but alice may see that document; it now uses a missing number.
- `WorkflowApiTests` expected 7 templates; main now seeds 9 with the two sourcing templates (not CAD). Expectation updated.
- `BrowserSession.AssertBannersAsync` read the top and bottom banner at two different instants; on a page that loads data after the first render (the CAD tab, the variants pages) they could differ. It now re-reads until both agree (up to 10 s). This fixed `CadTests` and `VariantsTests` in the full run.
- `AccessibilityTests`: 7/7 pass when run as a class. In full-suite runs the theme menu click during sign-in sometimes timed out (the click lands before the circuit is interactive); retrying the click made it worse and was reverted. Open: the full E2E run is still flaky there, and `SourcingTests` (3 tests: portal redirect to access-denied, a strict-mode locator clash on the certificate table, `/sourcing/coverage` scrolling sideways at 375 px) failed; those are sourcing's, not CAD's.
