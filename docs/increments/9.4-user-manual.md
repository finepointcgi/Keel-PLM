# 9.4 User manual (2026-10-30)

## Delivered
- `docs/manual/`: an illustrated user manual in Markdown. `README.md` is the table of contents, quick start, role guide, glossary and the list of what is not shipped; 24 chapters, one per area (getting started, navigation, parts, BOMs/variants/MBOM, documents and vault, workflow and e-signatures, change, baselines, markings, quality, CAD and FreeCAD, sourcing and portal, process, requirements, compliance, records, programs, output, notifications, audit, integration and TDP, migration, administration, operator guide).
- Real screenshots in `docs/manual/images/` (PNG, 1440x900, light theme; plus dark, high-contrast, compact and 375 px examples), captured by `tests/Keel.E2E/ManualScreenshotsTests.cs`. It reuses the E2E fixture (throwaway PostgreSQL, vault, Keycloak, real host) and its seeds, and runs only with `KEEL_E2E=1` and `KEEL_MANUAL_SCREENSHOTS=1`; otherwise it returns at once, so the normal suite is unchanged. Shots that fail are logged to `TestResults/e2e/manual-shots.log`; the run does not fail on them.
- The operator chapter only points to docs/ops, docs/setup.md and the integration docs; it adds no behavior.

## Regenerate the images
`KEEL_E2E=1 KEEL_MANUAL_SCREENSHOTS=1 dotnet test --project tests/Keel.E2E --filter-class "*ManualScreenshotsTests"` (needs Docker; about 10 minutes). Other E2E tests rewrite `docs/ux/screenshots`; run `git checkout -- docs/ux/screenshots` before committing.

## Not captured
The FreeCAD add-on's own windows (FreeCAD's, not Keel's), the full step-up flow after the sign-in screen, e-mail notifications, CAC/PIV sign-in.

## Checks done
Every relative link and image reference in docs/manual resolves; routes and tab names in the chapters were taken from the pages and the E2E tests.
