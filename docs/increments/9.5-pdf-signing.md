# 9.5 Digitally signed release packages (2026-10-30)

ADR-0051. Migration `0030_pdf_signing.sql`. Assumptions A64-A66. Operator guide: [ops/package-signing.md](../ops/package-signing.md). Manual: chapters 18 and 23.

## Delivered
- `Keel.Reports/Signing`: `PdfSigner` (invisible signature field with reserved space; detached CMS `ETSI.CAdES.detached` with chain, signing time, content type, message digest and ESS signing-certificate-v2), `PdfSignatureVerifier`
  (byte-range coverage, CMS integrity, certificate binding, chain to configured anchors at signing time, verdicts valid/untrusted/tampered/not signed/unreadable), `SigningKeyLoader` (PEM, PKCS#12, certificate store, OpenSSL provider; env/file password references; probe
  that the key matches the certificate), `SigningPolicy` (RSA 2048+, ECDSA P-256/384/521, SHA-256+), `DevSigningCertificate` (dev-only generator), `PackageSigningService` (identities, policy, preparing and recording signatures, verification).
- `ReleasePackageService` signs at generation: refuses (503) when signing is required and no identity is active, or the active key fails; stores the signed bytes; writes `rpt.artifact_signature` and `output.package.sign` in the artifact's transaction.
  `ArtifactView` gains `SignedBy` and `SignedAt`.
- REST (documented in `docs/reports/openapi.json`): `POST /api/v1/output/packages/verify`; administrator: `GET|POST /signing/identities`, `POST /signing/identities/development` (dev hosts only), `POST /signing/identities/{id}/activate|retire`, `GET|PUT /signing/policy`.
- UI: Administration > Package signing (`/admin/signing`); Output > Verify a package (`/output/verify`); a Signature column on Release packages.
- `scripts/verify-package-signature.sh`: verification with bash, xxd and OpenSSL 3 only.
- Migration 0030: `rpt.signing_identity` (guarded: never deleted, only activate/retire change, one active), `rpt.signing_policy` (singleton), `rpt.artifact_signature` (immutable). No private key, password or marking column. `signed_digest` is registered in `VaultReferences.NotVaultContent`.

## Decisions and assumptions (SIGN-n)
- SIGN-1 Certificate bundle is stored (public); private key and password are referenced, never stored. SIGN-2 Bundle must end in a self-signed root, which becomes a trust anchor. SIGN-3 RSA 2048+/ECDSA P-256, P-384, P-521 with SHA-256+ only; certificates signed with SHA-1 or MD5 refused.
- SIGN-4 One active identity at most; retired identities never sign again, are never deleted and remain trust anchors. SIGN-5 A key that fails at signing time refuses the package; no silent unsigned fallback. SIGN-6 "Required" policy is a singleton setting.
- SIGN-7 Development generator only when the host is Development or Demo (configuration can only switch it off). SIGN-8 OpenSSL-provider and certificate-store key sources use platform APIs and were not run against real HSM hardware.
- SIGN-9 PAdES-B-B style: invisible field on page 1, `ETSI.CAdES.detached`. SIGN-10 No trusted timestamp, no revocation evidence (air-gapped). SIGN-11 Signing time is the Keel clock, written both in the CMS and in `/M`. SIGN-12 12 KB signature space. SIGN-13 Earlier packages stay unsigned.
- SIGN-14 Trust anchors are the self-signed roots of configured identities. SIGN-15 Chain judged at signing time, downloads disabled, revocation not checked. SIGN-16 Any PLM role may verify; 64 MB limit; the file is not stored.
- SIGN-17 A Keel package is named in a verification only to someone who may read every object in it; the audit entry otherwise carries a hash prefix. SIGN-18 Bytes appended after signing are tampering. SIGN-19 Foreign roots cannot be added; foreign packages are checked with the script or a PDF reader.

## Tests
- Unit (`PdfSigningUnitTests`, partial `ReportsUnitTests`): banners and notices identical on every page signed vs unsigned; CMS content (chain, signing time, one signing-time attribute, signing-certificate-v2, detached); one flipped byte at three places, appended bytes and changed document information detected; untrusted without/with the wrong anchor; expired-since still valid, not valid at signing time reported; unsigned and unreadable files; RSA-2048 and P-384 (SHA-384); weak RSA and unsupported curve refused; key loading from PEM, encrypted PEM with file password, PKCS#12 with env password, wrong key caught, directory confinement, thumbprint mismatch; reservation overflow; the shipped shell script against OpenSSL (accepts, rejects changed, extended and wrong-root).
- Integration (`PdfSigningTests`, real host, PostgreSQL, vault): admin-only management and every refusal with nothing stored; activation, retirement and DB guards; dev generator gated by host and labelled; signed package end to end (banners per page, immutable signature row, audit, verify valid/tampered/appended/not signed, retire keeps old packages valid); required policy and failing key refuse without storing; SQL-free policy oracle for eight subjects (recorded package named iff `AccessPolicy` allows reading every marked object, audit names no package for others); HTTP surface and roles; the reports OpenAPI document regenerated and compared.
- E2E (`OutputTests`): administrator generates and activates the development certificate, a package is signed, downloaded and verified in the UI, a changed byte is reported as changed; banners and no horizontal scroll at 375 px. Axe routes `/output/verify` and `/admin/signing` added to `AccessibilityTests`.

## Not built / not verified
- Trusted timestamps (RFC 3161), OCSP/CRL embedding, PAdES B-T/B-LT/B-LTA; visible signature appearance; multiple signers or countersignatures; signing other PDFs (reports, exports).
- Real HSM and Windows certificate-store keys; Adobe Acrobat acceptance (checked with OpenSSL 4 only; Acrobat/pdfsig were not available here).
- Adding foreign trust roots to Keel's verifier; re-signing earlier packages.
