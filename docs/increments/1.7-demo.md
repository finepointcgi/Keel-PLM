### 1.7 Demo readiness: seed data, end-to-end tests, demo script (2026-10-28)
Container packaging (Dockerfiles, Helm, offline bundle) is the other half of 1.7 and is documented separately.

**Delivered**
- `src/Keel.Seed` (`keel-seed`, `scripts/seed.sh`): `--scenario demo` builds the fictional ORCA sensor pod **only through the module services** (the same DI registrations and gateways as `Keel.Api`): 63 parts, 74 usage lines over 5 levels, 12 documents (generated PDFs, a CAD placeholder), 58 revisions released through the real review workflow with e-signatures (reviewer ada, approver bob, signers carry `auth_time` = now), markings mix (ITAR XI(d) ORCA, EAR 9A610/3A611/6A003/6A004, EAR99 and open items, a TAA-0042 object, a KRAKEN part), and changes in flight: PR evaluating and open, Class I ECR awaiting the CCB, Class II ECR draft, ECN draft with revision B in work, ECN under review with the approver pending, ECN rejected by the approver, four change tasks (one started, one done). It records the realm users in `identity.user_directory` (realm JSON embedded in the tool), refuses a non-empty `plm.part_master` (exit 2, `--allow-non-empty` bypasses), prints the numbers for the demo script, and ends by verifying the audit chain with `AuditVerifier` (exit 3 when invalid). `--scenario scale` wraps `SyntheticBomGenerator` (bulk SQL, off by default). `--manifest` writes the summary as JSON.
- `tests/Keel.E2E` (xUnit v3, Microsoft.Playwright 1.61.0, PdfPig 0.1.16): the fixture starts throwaway PostgreSQL, SeaweedFS and Keycloak (dev realm with a patched redirect URI) in Testcontainers (tmpfs, random ports), migrates with `Keel.Api --migrate`, seeds the demo data, runs the real `Keel.Api` as a child process with its own checkpoint key and `Keel__Workflow__StepUpMaxAgeSeconds=30`, and drives Chromium. Skipped unless `KEEL_E2E=1` (`scripts/e2e.sh`). Failure screenshots, console logs and Playwright traces go to `TestResults/e2e/<test>/`; `fixture.log`, `api.log` and `migrate.log` are kept there too.
- Tests: (a) `HappyPathTests`: alice creates an ITAR part with an attribute, uploads and links a document, builds a two-level BOM, submits (ada reviewer, bob approver); ada and bob sign after a real Keycloak step-up screen; release; ECN with the impact panel; ECN review and release (B Released, A Obsolete, the release lock visible); audrey verifies the chain; the audit events of the scenario are checked in order. (b) `ExportControlTests`: lena (search, direct URL, restricted BOM rows), farid (TAA-0042 object visible, others not), carmen and alice (KRAKEN, program need-to-know), marking banners top and bottom on every page. (c) marked PDF download text (PdfPig). (d) console errors on 15 pages plus audit (only the known CSP inline-style notice of Blazor Virtualize is filtered) and keyboard reach of the navigation and the primary button. (e) phone width 375x812: no sideways scrolling of the page.
- Docs: `docs/demo-script.md`, additions to `docs/setup.md`.

**Decisions and assumptions**
- E-1 The dev realm has one approver (bob) and cannot supply a second; the reviewer slot only needs a viewer or higher, so ada (admin) reviews. **No realm change was made.** A second approver account would make two-approver flows demonstrable (add it to the realm JSON; the seed embeds the file).
- E-2 The seeded KRAKEN part is authored by a seed-only identity `kraken-eng` (programs KRAKEN and ORCA) because no realm user is on KRAKEN; it is not a login.
- E-3 Step-up is exercised by running the test host with the 30 second minimum window and waiting for the login to age; the production default (300 s) is untouched.
- E-4 The seeder's emptiness probe reads `plm.part_master` directly (administrative yes/no, no end user). `ArchitectureTests` exempts exactly that file (`Keel.Seed/DatabaseState.cs`); the other rules are unchanged.
- E-5 Seed numbering is deterministic on a fresh database, so the demo script quotes part, document and change numbers.
- E-6 `Keel.Seed` references `tests/Keel.TestSupport` for the scale scenario (one generator for tests and demos).

**Found and fixed by the E2E tests**
- At 375 px the top navigation did not wrap and widened every page; `.topbar nav` now wraps (`app.css`, additive).

**What the demo does not show yet** (also in the demo script): CAD integration (Phase 4), effectivity, baselines, MBOM, redlines (Phase 2), migration importers (Phase 3), ERP and other integrations (Phase 4), HA, backup, SIEM, idle-session lock and CAC/PIV (Phase 5), workflow template editor, delegation and escalation (Phase 2), second approver in the dev realm, containers and the offline bundle (separate 1.7 packaging work).

**Known limits**
- The browser tests wait about 30 seconds once for the step-up window; the whole suite runs in a few minutes.
- The first E2E run downloads Chromium (Playwright's installer) and pulls images if absent.
