# 9.5 Simplified flows (2026-10-30)

User feedback: the app felt too complicated (adding a part too hard, updating confusing, a document could not simply be linked to a part). This increment changes screens and wording only; every rule stays (ADR-0061, assumptions A73-A75). Migration 0040.

## Delivered
| Flow | Before | After |
|---|---|---|
| Add a part | Parts list > New part, then a page with name, type, unit, source, description, all attributes and ten markings fields. Minimum: list, New part, name, Create part = 4 interactions, with ~25 fields in view | Parts list > Create part, name, Create part = 3 interactions (2 from `/parts/new` or the palette); name and optional description in view, type/unit/source/markings as one line and one chip each with Change, optional attributes under More details, required attributes asked for. **Create and add another** keeps the form open |
| Update a part | Check out, edit, Save working copy, type a comment, Check in (5 interactions, 4 named steps) | **Edit**, edit, **Save** (3). Optional change note. **Discard changes** (with confirmation) undoes. Check out / Save working copy / Check in / Undo check-out remain under **More** |
| Released part | A disabled-looking page with a grey line | One line "needs a change order" and a **Start change** button that opens a change notice with the part filled in |
| Link a document | Create the document (no link field); open the part; Check out; Documents tab; type the number; choose type; Add link; type comment; Check in (about 9 interactions) | New document form: **Link to a part** picker (name, part, Create document = 4 interactions incl. choosing the part). Or on the part page **Add document**: one dialog attaches an existing document or creates a new one (Add document, search, choose, Add = 4) and does the check-out, link and check-in |
| Navigation | One group opens by default (already), 8-11 groups | Same, plus **Simple view** in the user menu (3 groups for a viewer) |
| Words | "Edit working copy", "Working copy (applied at check-in)", "New part/New document" | "Your changes", "Your draft (applied when you save or check in)", **Create part** / **Create document** (list, Home, palette); one-line `GlossaryHint` for version, revision, working copy, check out/in, markings where the terms stay |

New code: `Keel.Web/Services/SimpleFlows.cs` (chains and plain-language advice, no rules), `QuickDefaults.cs`, `Glossary.cs`; components `QuickPartForm`, `MarkingsDefaultPicker`, `ObjectPicker`, `AddDocumentDialog`, `PartEditBanner`, `GlossaryHint`; `Keel.Workspace/LastChoiceStore.cs`; `simple.css`; migration `0040_simplify_flows.sql`. Small hooks in `PartPage`, `PartDocumentsPanel`, `PartsSearch`, `DocumentsSearch`, `QuickActionsCard`, `PaletteActions`, `NavModel`, `MainLayout`, `UserMenu`, `ShellState`, `WorkspaceService`/`Models`, `KeelUi` (one DI line), `App.razor` (one stylesheet link). `PartNew` and `DocumentNew` were rewritten around the new components.

## Decisions
- Chains live in Keel.Web because a module may reference only Keel.Core; they hold no rule (ADR-0061).
- A document added to a part from the part page produces a new part version (it is a check-in) with the note "Added document D-nnnnnn".
- A document that was created but could not be linked stays created; the person is told (it cannot be rolled back: documents are never deleted).
- The Simple view is a preference, not an access rule.

## Not done / deferred
- No "Add to part" action on the document page (DocumentPage is being changed by another branch; the part page and new document form cover the paths asked for).
- Quick add shows retired-attribute values nowhere and does not offer classification at creation (still a part tab after check-in).
- Home empty states and the other modules' create forms (changes, baselines, requirements...) were not simplified; only the primary part and document paths were audited.
- The administrator cannot yet pick the default markings, type or source explicitly: the default is the list order (A73).
