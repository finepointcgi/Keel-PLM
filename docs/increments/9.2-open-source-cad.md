## Reader fixes (StepStructureReader)
1. **UTF-8 names**: Open CASCADE writes non-ASCII names as raw UTF-8; the file was decoded as Latin-1 and "Halterung für Ø5" came out as mojibake. Now valid UTF-8 is read as UTF-8, otherwise Latin-1 (also `StepProductCounter`). Also the `\S\` escape of edition 1/2 files.
2. **Two PRODUCT entities with one id** (configurations, copied shapes) gave two parts with one number and two lines; now merged into one part and one line (quantities add).
3. **Protocol detection** looked at the whole header (a file name containing "442" made AP203 look like AP242); now only `FILE_SCHEMA` decides.
4. **Edition 3 `DATA('name',(schema));`** was reported as "no DATA section", and further DATA sections (with ANCHOR sections between) were ignored; both handled.
5. **Explicit quantities**: `QUANTIFIED_ASSEMBLY_COMPONENT_USAGE` (simple instance and the complex-instance form with `PRODUCT_DEFINITION_RELATIONSHIP`) is read; a `COUNT_MEASURE` is applied as that many pieces, any other measure is noted on the line and not applied (a length is not a piece count). Complex instances carrying a usage are parsed; all others are still skipped unread. Note: these forms were tested with hand-written text (Open CASCADE does not write them), so they are verified against the standard's shape, not against a real exporter.
The real files exposed nothing else: the 3-level, repeated sub-assembly, AP214, AP242 and AP203 cases read correctly with the original code.

## Assumptions
- **OSS-CAD-1** The add-on is a direct HTTPS client (stdlib), not a wrapper of `keel-cad`. `keel-cad` has no device or interactive flow, so the add-on reuses its token mechanism (env var or file) and adds a token command; no flow was invented.
- **OSS-CAD-2** The Keel part number is the custom property `KeelPartNumber`; a part without it is sent without a number (Keel proposes a new part) with a warning, or refused when "require part numbers" is set.
- **OSS-CAD-3** Quantity is the count of usages (`App::Link` objects plus `ElementCount` of arrays); find numbers are `KeelFindNumber` or 10, 20, ... in order; folders are transparent; loose geometry is not a BOM line.
- **OSS-CAD-4** Drawings are not in the structure (closed schema); TechDraw pages give references and `drawing-of` associations. A declared reference asserts the drawing was regenerated.
- **OSS-CAD-5** The work folder state is `keel-cad`'s `.keel-cad/state.json`, shared.
- **OSS-CAD-6** FreeCAD object model as described in `fcdoc.py`; now verified in FreeCAD 1.1.4 (headless script, live E2E, GUI check); FreeCAD 1.0 and assemblies with joints not tried.
- **OSS-CAD-7** Saving a FreeCAD file changes its bytes, so check-in saves only documents modified in the session and relies on hashes.
- **OSS-CAD-8** The STEP part number is `PRODUCT.id` (FEAT-CAD-7 unchanged); fixtures come from one exporter (Open CASCADE). Other vendors' files may differ.
- **OSS-CAD-9** `keel-cad watch` uploads changes of tracked files only (polling); new files need `add`; structures go through `bom push`.
- **OSS-CAD-10** The KiCad and Onshape/Fusion recipes were not run against those programs.

## Not done
- Dialog appearance and real clicks in the FreeCAD GUI; FreeCAD on Windows/Linux and 1.0; HTTPS with a private CA against the real host.
- STEP placements (positions) and mapped-item based reuse are not read; the neutral structure has no field for them. Assembly constraints, PMI, effectivity, `CONTEXT_DEPENDENT_SHAPE_REPRESENTATION` are ignored. Very large files (64 MiB limit) were not timed.
- Real KiCad, Onshape and Fusion exports were not tried. No commercial plug-in (see cad-plugins.md).
- `docs/CLAUDE.md`, `docs/assumptions.md` and `docs/adr/README.md` were left for the coordinator; `FEAT-CAD-7` in increments/8.0-cad.md is superseded in part by fix 5.

## Real-run additions (2026-10-29)
Bugs found and fixed: `status` reported 0 stale for a model with an out-of-date drawing (server `staleCount` counts only uses); the workbench icon was empty (`__file__` is undefined when FreeCAD runs `InitGui.py`); check-out opens files by real path (symlinked folders made FreeCAD open a second copy of the model). OSS-CAD-7 note: re-saving an unchanged document did not change its bytes in 1.1.4. New: `scripts/live_server_check.py`, `freecad_gui_check.py`, `run_gui_check.py`, `AddOnLiveTests`; `test-addons.sh` runs the real-FreeCAD stages when FreeCAD is installed.
