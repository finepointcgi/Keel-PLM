### 6.0 In-browser file viewer (UX-2, 2026-10-28)
Design record: [ADR-0027](../adr/0027-file-viewer.md). Third-party notices: [docs/third-party/viewer.md](../third-party/viewer.md).

**Delivered**
- `Keel.Viewer` (namespace `Keel.Viewing`): `FileSniffer` (type detection by signature/structure AND extension), `ViewerService` (the single place that refuses: content, size, gates; concurrency bound), `ViewerCsp`, `ViewerOptions` (`Keel:Viewer`).
- `Keel.Core.Viewing`: `FileFormats`, `IViewableFileSource`, `ViewableFile`, `IFileViewGate`. Implemented by `DocumentService` in the new file `DocumentService.View.cs` (authorize Read then Download, verified read, PDF stamping through `PdfMarker`, `document.view` audit).
- Routes (cookie session): `/viewer/documents/{n}/files/{id}` (standalone page), `/viewer/documents/{n}/primary`, `/viewer/meta/…`, `/viewer/content/…`. Own CSP on viewer routes and assets only; sandboxed CSP on content.
- Viewers: 3D (STL, glTF/GLB, OBJ, STEP/IGES in a worker; orbit, fit, standard views, wireframe, bounding box, measure, section, explode, screenshot with burned-in markings), PDF (pdf.js), images (PNG/JPEG/GIF/WebP/SVG as image only), and a facts-and-download panel for everything else.
- UI: "View" next to "Download" in file lists, type badges, "View" for the primary file of linked documents on part pages (this is also the "open drawing" shortcut), links are full navigations.
- Vendored assets with `manifest.json` and hashes; `tools/viewer-vendor` regenerates them (maintainer only).

**Tests:** see the final report for counts. Unit: sniffer (spoofing), CSP policies, asset manifest and notices, page rendering, View links, architecture rules, service rules. Integration (real PostgreSQL and vault): authorization matrix, audit, marked PDFs equal download semantics (PdfPig), integrity failure, size limits, gates, HTTP headers, strict CSP on every other route. Playwright (`ViewerTests`): STL/STEP/GLB/glTF/OBJ/PDF/PNG/SVG rendering with pixel read-back, overlay, burned-in screenshot, measure, section, explode, keyboard, 375 px, tamper guard, errors, denials.

**Decisions and assumptions** (VWR-n; not added to `assumptions.md`)
- VWR-1 Viewing is its own audited action `document.view`; success of describing a file for the page is not audited (subset of `document.read`).
- VWR-2 View needs Read AND Download. Gap found: `AccessPolicy` grants Read and Download to the same roles, so a "read but not download" user cannot exist today; there is no view-only mode. The Forbidden path exists and is unit-reachable only through the interface.
- VWR-3 Content detection never trusts the extension or stored media type; strong signatures win over the name (with a warning), weak text formats need both.
- VWR-4 3D and image bytes are delivered unstamped with an overlay (A10 puts them in a marked ZIP for download). Residual risk documented in ADR-0027.
- VWR-5 pdf.js, not the browser's PDF plugin. No annotations, forms or in-PDF search.
- VWR-6 A DOM watchdog restores banners and hides the file on tampering; a handling aid, not DRM.
- VWR-7 Whole file is verified in memory before sending; no Range support.
- VWR-8 `IFileViewGate` is the extension point for the quarantine/scan check of the compliance wave.
- VWR-9 Limits: 100 MiB 3D, 50 MiB PDF (also bounded by `MaxPdfStampBytes`), 50 MiB images, 5 M triangles, 8 concurrent reads.
- VWR-10 A PDF that cannot be stamped is refused rather than shown unmarked.
- VWR-11 Standalone viewer pages are rendered with `HtmlRenderer`, have no `@page`, and are covered by their own architecture rule instead of `PageFrame`.
- VWR-12 STEP/IGES use occt-import-js (LGPL-2.1). The worker needs `'unsafe-eval'` (Embind) in addition to `'wasm-unsafe-eval'`; confined to the worker's own response. `EnableCadImport=false` switches it off. Conclusions in the ADR.
- VWR-13 Z-up (STL, STEP, IGES) vs Y-up (glTF, OBJ) is a guess with a toggle; units are shown as mm only for STEP/IGES, otherwise "units".
- VWR-14 Namespace is `Keel.Viewing` because `Keel.Viewer` would shadow identifiers named `Viewer` in other modules' tests (found in `BomWorkingCopyTests`).
- VWR-15 `.gltf` with external files is refused with a message (upload a `.glb`); Draco/KTX2/meshopt are not included.

**Not done / limits**
- Source archives for the LGPL component are not in the offline bundle yet (release engineering).
- Thumbnails, BOM-level explode, PDF search, annotations.
- pdf.js standard-font and CMap data are not vendored: PDFs that rely on non-embedded standard or CJK fonts fall back to generic fonts.
- Not verified: Safari/Firefox, a real GPU, models over a few hundred thousand triangles, performance of 100 MiB STEP files, the FIPS host.
