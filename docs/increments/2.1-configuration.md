### 2.1 Configuration management: baselines and effectivity (2026-10-28)
Design record: [ADR-0021](../adr/0021-baselines-and-effectivity.md).

**Delivered**
- Migration `0008_configuration.sql` (schema `cfg`): effectivity contexts and blocks, effectivity columns on BOM usage rows (line alternatives, `alt` ordinal), revision effectivity with history, change-notice effectivity, baselines (header, items, pinned documents), baseline lifecycle and types as data, seeded workflow template `baseline-establish-review`, immutability and overlap triggers.
- `Keel.Bom`: `BaselineService` (create, search, get, documents, update draft, establish, supersede, archive, verify), `BomService` (config specs `Effectivity` and `Baseline` for explosion, lazy expansion, summary, CSV, where-used with a unit; baseline against baseline, against current, unit against unit, CSV), `EffectivityService` (contexts, revision effectivity view), `RevisionEffectivityService` (the supersession rule), `BaselineWorkflowGateway` (e-signature establishment).
- `Keel.Core` interfaces `IRevisionEffectivity`, `IDocumentPinProvider`; `Keel.Documents.DocumentPinProvider`.
- REST: `/api/v1/baselines` (search, create, get, items, items/export.csv, summary, documents, verify, compare, compare-current, establish, supersede, archive, review, workflow), `/api/v1/effectivity/contexts`, `/api/v1/parts/{n}/effectivity`, `/bom/compare-units`, `/baselines`, unit parameters on `/bom`, `/bom/export.csv`, `/bom/summary`, `/where-used`, `PUT /api/v1/changes/{n}/affected/{id}/effectivity`; cookie download routes for the UI.
- UI: Baselines list, create, detail (items grid, documents, actions, review panel), baseline compare, compare units, "As of serial, lot or date" and "Baseline" in the BOM view, effectivity column and editor, effectivity on ECN affected objects, nav link.
- `Keel.Change` edits: optional effectivity on `AddAffectedCommand`/`AffectedObjectView`/snapshot, `ChangeService.SetAffectedEffectivityAsync`, release rule in `ChangeWorkflowGateway`, DI in `ChangeModule`.

**Tests:** 269 unit (36 new: rules, form state, bUnit components, architecture rule for baseline items); integration: 14 effectivity, 13 baseline, 2 baseline document, 2 REST, 1 performance gate, plus 5 existing tests updated for intended changes (Phase 2 stubs gone, `baseline` template listed). Performance in the ADR.

**Decisions and assumptions** (CFG-n; not added to `assumptions.md`)
- CFG-1 Baselines and effectivity live in Keel.Bom, not a new module (shared explosion/redaction internals).
- CFG-2 One item row per occurrence; root is seq 0; a baseline may be taken from Latest, LatestReleased or as of a unit (as-built).
- CFG-3 Sign-off is data per baseline type: Design is established directly by authors/admins with a reason; Release and Product (or "require sign-off") only through the signed review; enforced by trigger.
- CFG-4 Markings start from the root's, must cover every item and pinned document, minimal cover only with confirmation; creator needs Read on all items (count-only refusal).
- CFG-5 A unit may give serial, lot and date; lines of a dimension not given are excluded; lines without effectivity always apply.
- CFG-6 Redacted lines still show their effectivity range.
- CFG-7 Alternatives of one find number must not overlap and share dimension and context; path suffix `~n`.
- CFG-8 Restricted lines in comparisons match only on the same hidden part; hidden revision changes show as "Restricted item changed".
- CFG-9 Supersession rule: effective-from-N releases the new revision, cuts every other Released revision back to below N, obsoletes those left serving nothing; no effectivity means classic full supersession; ranges are open at the top and agree in type and context.
- CFG-10 Serials and lots are integers 1..9,999,999,999; named blocks map to lots per context; dates are UTC day numbers.
- CFG-11 Contexts are immutable, created by modify-capable users, visible by program.
- CFG-12 As-built resolution uses Released revisions only (covering range, else highest Released); gaps resolve to the highest Released.
- CFG-13 Baseline integrity is a content hash recomputed from live rows (signatures, submission, establishment, verify).
- CFG-14 Where-used for a unit requires a released parent revision.
- CFG-15 Baseline roots must be assemblies; at most 250,000 items.
- CFG-16 Documents pin at creation (references: latest Released else latest); shared iterations pin once.
- CFG-17 Renumber keeps alternatives on one find number.
- CFG-18 The UI creates baselines with the root's markings plus a confirmation checkbox; explicit markings are REST only.

**Not done / not verified**
- EBOM/MBOM, document effectivity, effectivity of documents or revision ranges editing outside change notices.
- The UI was not driven in a browser: no Keycloak/dev stack was started (memory); covered by bUnit, REST and service tests only.
- Baseline review wording in the shared start dialog still says "the part".
