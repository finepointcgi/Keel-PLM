# Gap wave A: UI completeness (increment 7.4)

Design: [ADR-0031](../adr/0031-list-sorting-and-admin-completeness.md). No migration.

## Delivered
- Server-side sorting for parts, documents, changes, baselines, MBOMs and workflow tasks: `Keel.Core.SortMap`/`SortSpec` whitelist, `PartService.SortKeys` etc., optional `sort`/`dir` on the REST list endpoints (400 for an unknown key), `DataTable.ServerSort` + `OnServerSort`, sort kept in the address (`?sort=name&dir=desc`). Baselines and MBOM pages gained a pager (they showed only the first 50).
- MBOM "Security markings" tab (`MbomMarkingsPanel`) over the existing `ChangeMarkingsAsync`; `/admin/supply-types` over `SaveSupplyTypeAsync`, which now takes a reason to retire or restore (`SaveSupplyTypeCommand.Reason`, REST `reason`) and audits before and after.
- All inline admin confirms use `ConfirmDialog` (import, class move/retire, lifecycle publish and migrate, template publish, reasons, lists, attribute retire). Heading outline fixed on 16 pages; `EmptyState` title is a paragraph.
- `?tab=` deep links on object pages (`TabSet.FromUri`, `TabSet.OnNavigation`).
- Bug fix found by the tests: `Markings` equality compared sets by reference, so "markings are unchanged" checks never fired (Parts, Documents, Changes, MBOMs); `Markings` now has value equality.

## Assumptions
- GAP-A-1: Sort keys per list are the visible columns; unsortable columns (version of a baseline, markings, reconciliation status, configuration) stay unsortable. Text keys sort case-insensitively with the database collation; nulls sort last in both directions; the unique number is the final tie-breaker. Without a sort each list keeps its old default order.
- GAP-A-2: No e-signature step-up for MBOM markings changes or supply types: no other markings or administration change asks for one (step-up binds workflow signatures only). The reason is the control; both are audited. The MBOM markings form is offered only while the latest revision is In Work (the service enforces the lifecycle's lock).
- GAP-A-3: A server-sorted table does not save its sort in the per-user layout; the address is the single source. Hand-edited or stale `sort`/`dir` values fall back to the default order instead of an error page.
- GAP-A-4: The workflow task list is not paged, so its sort is applied in memory after redaction (redacted tasks sort last).
- GAP-A-5: Sorted columns have no dedicated indexes; sorting happens inside the access-filtered set. Add indexes if a list grows far beyond tens of thousands of rows.
- GAP-A-6: The address is updated with `history.replaceState`, so the circuit's `NavigationManager.Uri` is stale until the next navigation; pages read the address once on load. For tabs, the address's tab is applied only when the address is new, so a user's own tab choice survives reloads after actions.
- GAP-A-7: `EmptyState` titles stopped being headings; a deliberate trade to keep outlines valid on list pages.

## Tests
Unit (844 in total, all passing): `SortMap` and whitelist rules, every list page's keys against its module's whitelist, `DataTable` server mode, tab deep links, markings equality, confirm-dialog rule, `HeadingOutlineTests` (one h1, no skipped level, pages and components). Integration: `SortingTests` (6 lists, SQL-oracle: restricted order equals full order minus hidden rows, totals unchanged, injection keys refused), `MbomAdminTests` (markings change and supply types, audit, fail closed). E2E: `GapATests` (5, including 375 px) and the updated `AdminTests`.

## Not built
Sorting of the reconciliation status and of the baseline configuration text; paging for the task list; indexes for sorted columns (GAP-A-5).
