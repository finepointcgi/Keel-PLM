# 9.6 E-mail verification, bounce handling and the message-broker sink (2026-10-30)

ADR-0055. Migration 0034 (`ntf.email_verification`, `ntf.email_address_health`, `ntf.email_bounce_event`, two columns on `ntf.preference`). Assumptions A79 to A81. No new module.

## Delivered
- **Verification** (`Keel.Notifications/Email/EmailVerification.cs`): `IEmailVerification` / `EmailVerificationService` (request a link, redeem a token), `EmailVerificationOptions`, `VerificationMailContent`.
  Mail goes only to the verified, unsuppressed address (`NotificationWriter` queue condition and `EmailNotificationChannel` send-time check). `EmailPreferenceService.GetAsync` reports
  verified / pending / suppressed (suppressed only for an address the user had verified); saving a different address clears the verification.
- **Bounces** (`EmailBounces.cs`, `DsnParser.cs`, `BounceMailboxReader.cs`): `EmailBounceService` (record, administrator health view, lift suppression, purge), `BounceTags` (HMAC tag that every
  mail carries when `TagSecret` is set), `EmailBounceOptions`, a hand-written RFC 3464 and RFC 5965 reader, and the optional hosted mailbox reader.
- **REST**: `POST /api/v1/notifications/email/bounces` (`NotificationEmailEndpoints`, policy `plm-integration`), documented in `docs/ops/email-verification-and-bounces.md`.
- **UI**: confirmation state and "send me a link" on Notifications > Preferences, `/notifications/verify-email/{token}` (`VerifyEmailPage`), `/admin/email` (`EmailDeliveryPage`, nav link and
  Administration overview entry), the **Message broker** kind with its fields on the sinks page.
- **Broker sink** (`Keel.Integration/BrokerSink.cs`, RabbitMQ.Client 7.2.0, Apache-2.0 OR MPL-2.0): AMQP 0-9-1 with publisher confirms on mandatory persistent publishes, event id as message id and
  `x-keel-idempotency-key`, optional signature headers, TLS 1.2/1.3 with CA bundle and mutual TLS, SASL EXTERNAL, secrets by name, allow-list and SSRF check on every connection, optional exchange
  declaration. The old `BrokerSink` that threw `NotSupportedException` is gone, the fan-out no longer skips broker sinks, `SsrfGuard.CheckHost` was factored out of `CheckUrl`.
- **Docs**: ADR-0055 (ADR-0032 section 4 annotated), ops notes (`email-verification-and-bounces.md`, `notifications.md`, `integration.md`), manual chapters 19, 21, 24 and the README list, the
  licence inventory (`docs/review/legal-open-source.md`: RabbitMQ.Client and the test-only container image), `docs/review/export-control.md`.

## Tests
- Unit (`EmailVerificationBrokerUnitTests.cs`): DSN and abuse-report parsing and classification, tag binding, sanitising, mail text, `Compose` header, option validation, broker configuration validation
  (protocols, host allow-list, TLS acknowledgement, authentication required, secrets, exchange and routing key rules, permanent versus retry on missing host or secret).
- Integration, PostgreSQL (`EmailVerificationTests.cs`): no mail before confirmation and one pointer-only mail after, token stored only as a hash and absent from the audit log (SQL oracle),
  single use, wrong user, replaced, expired and address-changed links, rate limits and the no-enumeration answers, relay refusal voids the link, two hard bounces / soft bounces / unknown addresses /
  complaint, queued mail skipped after suppression, administrator view and denials, lifting and re-verifying, purge keeps suppressions, mailbox reader (tagged accepted; forged, untagged, wrong
  secret, plain mail, oversize and settling files), the REST endpoint (401, 403 for other roles, 200 with counts, 400 for bad input). The existing `EmailChannelTests` now confirm the address first.
- Integration against a **real RabbitMQ 4.1** in Testcontainers (`BrokerSinkTests.cs`, 11 tests): persistent publish with message id, idempotency key, signature and a schema-valid envelope; fixed
  routing key and default exchange; exchange creation; unroutable messages retried with the same id; dead letter and requeue with duplicate delivery; broker stopped and started; wrong credentials;
  TLS verified and refused for a foreign CA; mutual TLS with a password and with SASL EXTERNAL; a withheld event never reaches the broker (broker-side count); SSRF refusal at connect time.
- E2E (`EmailVerificationTests.cs`, in-process SMTP relay added to `E2EFixture`): save address, mailed link, generic invalid link, keyboard confirmation, suppression notice, administrator lifts it
  with the keyboard, user confirms again, phone width, axe audit of every state; `/admin/email` is also in the all-pages audit list. Manual screenshots: `email-verification-preferences`,
  `email-verification-confirm`, `admin-email-delivery`, `admin-integration-sinks-broker`.

## Decisions to know
- Kafka and AMQP 1.0 were not built (native client library and FIPS review for Kafka; a second protocol is additive through `protocol`).
- Existing opted-in users must confirm once after the migration; nothing is grandfathered.
- The bounce endpoint reuses the `plm-integration` role instead of adding a role to the identity provider realm; the mailbox reader needs the HMAC tag because anybody can mail the bounce address.
- A hard-bounce threshold of two, and mailbox-full (5.2.2) as soft, are defaults a site can change or accept (A80).

## Not done
- AMQP 1.0, Kafka, batched publisher confirms (one confirm per message), VERP return paths, an inbound SMTP listener, DKIM or SPF handling, manual suppression of an address by an administrator.
- Brokers other than RabbitMQ were not tested. Real relays (Postfix, Exchange) were not tested against the mailbox reader; the parser follows the RFCs and the test files are hand-built.
