# Increment 3.0: migration from Teamcenter and Windchill

Design: [ADR-0023](../adr/0023-migration-importers.md). User docs: [docs/migration](../migration/README.md). Built in a worktree off `main` after Phase 1, in parallel with Phase 2a (baselines, effectivity) and 2b (admin UI, classification).

## Delivered
* Migration `0010_migration.sql`: schema `mig` (`batch`, `id_map`, `quarantine`, `report`, with immutability guards), nullable provenance columns on plm/chg tables (`imported_batch_id`, `source_id`, `legacy_revision`, `legacy_properties`, `legacy_number`), least-privilege grants.
* Library `Keel.Migration`: readers (PLM XML streaming, Windchill JSON and CSV, canonical package, zip or directory), canonical staging model, mapping file and validator, markings mapper, pure `Mapper` (plan + problems), `ImportWriter` (plain SQL honouring every guard), `Importer` (dry-run = same code in a rolled-back transaction; chunked, resumable load; audit at batch or object granularity), `Reconciler`, reports (JSON, Markdown, CSV; hash-gated), `BatchQueries`, `MappingTemplate`.
* `Keel.Core.IContentStore` (+ `VaultContentStore` in Keel.Documents, new file) and `IClassificationLoader` (default throws `NotSupportedException` naming Phase 2b).
* CLI `keel-import` (`src/Keel.Import`): inspect, map-template, validate, dry-run, load, reconcile, report; no implicit target; exit codes 0-6, 130.
* Admin pages `/admin/migration` and `/admin/migration/{id}` (UNCLASSIFIED; counts, codes and source ids only; viewing is audited).
* Synthetic fixture generator (`tests/Keel.Migration.Fixtures`): one logical product written as canonical, PLM XML, Windchill JSON and Windchill CSV, 11 injectable defects, a scale generator and a streaming 200 MB PLM XML writer.
* Docs: README, PLM XML subset, Windchill extract spec, mapping reference, runbook, sources.

## Assumptions and decisions (MIG-n)
| # | Decision |
|---|---|
| MIG-1 | The formats are subsets we specify from public documentation; no real export was available. Real samples are required (README, "What we need from you"). |
| MIG-2 | The mapping file is JSON with comments and trailing commas, not YAML: no extra dependency in an air-gapped build. Unknown members are errors. |
| MIG-3 | Source (`SRC-*`) errors block the whole package even with `--quarantine`; mapping and validation errors quarantine the object (and, via `DEPENDENCY-FAILED`, the objects that need it: no BOM with a silently missing line). |
| MIG-4 | Markings combine restrictively over every matching rule and every iteration; conflicts are errors; no determinable jurisdiction is an error; `defaultMarkings` applies only when no rule set a jurisdiction, is never merged into a rule result, and is listed for review. Imported changes are raised to cover the parts they list. |
| MIG-5 | Revision labels are assigned in source order (`auto`: distinct dates, else comparable labels, else an error; `revisions.explicit` resolves it); `sequence` policy by default, `keepWhenValid` optional; the original label is always in `legacy_revision`. |
| MIG-6 | Properties without a Keel attribute are preserved in `legacy_properties` (master, revision, iteration) and reported; the original author survives user mapping in the `_source` block. |
| MIG-7 | Only the current lifecycle state is loaded; the history is kept in `legacy_properties`. Under Review is imported without a workflow instance (warning). |
| MIG-8 | Missing timestamps are inherited from the parent, then from the package export date; without either, an error. |
| MIG-9 | A load needs the successful dry-run report (unmodified, same package manifest hash, mapping hash, quarantine setting; same validation result at load time). |
| MIG-10 | `mig.id_map` stores a hash of the mapped object; a changed source or mapping for an imported object is `LOAD-CONFLICT`, never an overwrite; new revisions after the imported ones are appended. |
| MIG-11 | Dry-run: one rolled-back transaction, same code; vault checked, not written; change numbers are synthetic so sequences are not consumed. Load: chunks of 100 objects, a savepoint per object. |
| MIG-12 | Changes: numbers from the Keel sequences (source number in `legacy_number`) unless the source number already fits `PR|ECR|ECN-nnnnnn`; Class I notices need a Class I request approved in the source (else error); tasks are not imported; one `imported` history row per change. |
| MIG-13 | BOM: items with lines become Assemblies (`assemblyWhenHasBom`); missing find numbers are assigned after the highest used (counted); EA quantities must be whole and designators equal the quantity; cycles are detected on the union graph of all iterations; effectivity text is preserved in the line's notes (Phase 2a). |
| MIG-14 | PLM XML datasets on a part revision become a synthetic document `<number>-FILES` linked with `describes`. |
| MIG-15 | Source users map to Keel usernames (they need not have signed in); the rest use `users.default` (flagged) or are errors. |
| MIG-16 | Audit: `batch` granularity by default (5 events per load); `object` adds one event per master, document and change. |
| MIG-17 | Reconciliation recomputes the source side from the package as it is now; it also reports imported objects the package no longer plans. |
| MIG-18 | Report files are CUI-handling artifacts; the UI shows counts, codes and source ids only. Problem messages can quote source values truncated to 40 characters. |
| MIG-19 | `--max-errors` limits printed problems; the report files always list all. |
| MIG-20 | Classification assignments are staged and counted; loading is `NotSupportedException` (Phase 2b). |
| MIG-21 | No implicit database target; the importer runs as `keel_app` and never disables a trigger. |
| MIG-22 | The architecture test allows `Reconciler.cs` (and only it) to select from marked tables without the read filter: an administrative comparison returning counts and ids. |

## Tests
* Unit (`MigrationTests`, `MigrationPageTests`): 38 cases: every reader against the same logical product (inventory counts, cross-format plan equality), unknown-element reporting and preservation, DTD refusal, CSV quoting, zip packages, unsafe paths, 10 malformed variants plus cascades and cross-format codes, markings (fail closed, restrictive combination, scalar conflicts, default semantics, a 500-round randomized "never weaker than any matching rule" property), mapping file validation, report hash stability and tamper detection, CSV formula neutralization, classification `NotSupportedException`, the page's error path.
* Integration (`MigrationLoadTests` 17, `MigrationCliTests` 5, `MigrationPerformanceTests` 3), real Postgres and SeaweedFS, no mocks: dry-run writes nothing (row counts, audit head, sequences unchanged, nothing in the vault) and equals the load; history, timestamps, authors, iteration sequence, locked releases and the guard triggers afterwards, plus native check-out/check-in continuing from an imported iteration; files in the vault with verified hashes; idempotent load and fault-injection resume; conflicts; fail-closed markings with quarantine and defaults; the dry-run gate (forged report, changed mapping, changed package, quarantine mismatch); change history with no workflow artefacts; audit events and chain; access control equal to native objects for three subjects; reconciliation (clean, altered BOM quantity via a superuser bypass, package file changed after load); source errors blocking despite quarantine; number collisions; the admin viewer's data; CLI exit codes.
* Suites at the end of this increment: see the report that accompanies the merge (unit 233 -> 271 passing; integration 177 -> 202 passing).

## Measured performance (development machine, Apple silicon; Postgres 17 and SeaweedFS in Docker on tmpfs)
| Scenario | Result |
|---|---|
| 10,000 parts, 18,000 revisions, 26,000 iterations, 40,000 BOM lines, 500 files (1.0 MB) | parse + map + validate 0.7 s; dry-run 31.7 s; load 32.7 s (about 2,900 rows/s; 96,000 rows); reconcile 0.5 s; 5 audit events |
| Audit granularity, 2,000 parts + 50 documents | batch 6.4 s (5 events); object 7.3 s (2,055 events); +0.44 ms per object. Recommendation: `batch` for routine imports, `object` when every object must be searchable in the audit log. |
| 200 MB PLM XML (12,389 parts, 16 KB of ignorable bulk each) | read + hash 0.8 s; managed heap growth 47 MB; read + map of the whole file 1.2 s, peak managed heap 119 MB (test process, includes the retained plan) |
Caveats: the 200 MB file was fully generated (no extrapolation) but its bulk is ignorable `Representation` text; a real export with 200 MB of mapped data keeps more data in memory (memory scales with the extracted data). Load memory in the first row (peak managed heap about 394 MB) includes the generator's 10,000-part model held by the test process. The vault was small-file, local; large files are bounded by vault throughput.

## Not done / not verified
* Real Teamcenter and Windchill exports (see the README list).
* The admin pages were **not** opened in a browser: the UI requires the OIDC stack (Keycloak), and the coordinator's dev stack was off limits and a second Keycloak did not fit in the shared Docker VM memory. They are covered by compilation, the PageFrame architecture rule, a bUnit render of the error path, and an integration test of the data they read.
* Effectivity (Phase 2a), classification loading (Phase 2b), workflow history and signatures, change tasks, CAD structure semantics, markup, intermediate states.
* The existing change UI does not yet display a "migrated record" badge; the flag is `chg.change.imported_batch_id` and the `imported` history entry (shown in the change history).
* PLM XML classification export is not written by the fixture generator (the reader supports it via `UserData type="Classification"`).
