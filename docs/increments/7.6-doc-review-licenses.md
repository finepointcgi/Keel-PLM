## Delivered

### 1. Document review and release through the workflow engine
- `Keel.Documents.DocumentWorkflowGateway` (new file; registered in `Program.cs` and `SeedHost`). Submit, tasks, e-signature meanings with step-up, release locking the revision, rejection, cancel and reassign all go through the existing engine, as for parts.
- Migration 0017: In Work <-> Under Review of every `document-default` lifecycle version become `workflow` transitions; seeded template `document-release-review` v1.
- UI: "Review & release" tab on the document page (`DocumentReviewPanel`: status, progress map, submit dialog, cancel, release history); manual "Move to Under Review" is disabled with the reason; task and workflow pages link to documents; start dialog and task messages name the object ("document").
- API: `POST /api/v1/documents/{number}/review`, `GET /api/v1/documents/{number}/workflow`.
- Integration: `document.released` carries `via = workflow` (schema enum `admin | workflow`, ERP contract text updated); watchers are told about entering/leaving review through `INotificationSink`; the workflow timeline source and map already handled documents.
- Signed content: description, document type and every file (role, name, media type, size, SHA-256).

### 2. Offline bundle completeness
- `deploy/offline/third-party-sources.json`: SHA-256 pins for the occt-import-js source (tag 0.0.23), OpenCascade at the commit its submodule pins (`d2abb6d8...`), and the npm package the shipped files came from; plus the components compiled into shipped files.
- `scripts/offline-compliance.sh` (called by `package-offline.sh`; options `--sources-cache`, `--os-sources-dir`, `--no-compliance`): fetch once and verify, `sources/` + `SOURCES.txt`, `licenses/`, SBOM, notices, bundle check.
- `src/Keel.SbomTool` (`keel-sbom`): `generate` (CycloneDX 1.5 `sbom/keel-plm.cdx.json` and `THIRD-PARTY-NOTICES.md`, offline, deterministic, `--strict`), `sources`, `verify`.
- `scripts/verify-offline.sh`: 21 new checks; BUILD-INFO records compliance and "legal-review pending".
- Dockerfile copies the viewer licence texts to `/app/licenses` (`.dockerignore` re-includes them; checked with a scratch build of the context only).
- Docs: `docs/third-party/legal-review.md` (new), `viewer.md` (open item closed, review still pending), `docs/ops/offline-install.md`.

## Assumptions (GAP-C-n; not added to assumptions.md)
- GAP-C-1 Documents reuse the part template shape; In Work <-> Under Review are workflow-only for documents (like A28 for parts). Administrators keep the audited override.
- GAP-C-2 The e-signature covers description, document type and the full file list with SHA-256; file bytes are covered through their hashes (the vault re-verifies bytes on download).
- GAP-C-3 A quarantined file blocks submission and release (the scanner can quarantine mid-review).
- GAP-C-4 Custom lifecycle versions that tag the review transitions `manual` cannot be reviewed (the gateway says so); migration 0017 corrects every existing version of the family.
- GAP-C-5 Documents already released by override stay released; no retroactive review.
- GAP-C-6 `document.released.v1` `via` widened to `admin | workflow` (additive for consumers that read it as a string; consumers that validate `const admin` must update).
- GAP-C-7 Watchers hear about entering/leaving review from the gateway; releases reach watchers through the outbox, as before.
- GAP-C-8 Source archives are fetched at bundle build time into a cache and verified by pinned SHA-256; GitHub-generated archives could change bytes (build stops; see legal-review item 5).
- GAP-C-9 The SBOM scope is the three shipped projects' NuGet packages, the viewer files, fonts and image pins; OS packages come from `syft` image SBOMs when available and their source only via `--os-sources-dir` (otherwise stated NOT INCLUDED).
- GAP-C-10 The Emscripten runtime entry is "unconfirmed" (not inspected in the binary).
- GAP-C-11 The offer text (three years) and the `[Company]` contact are drafts for counsel.
- GAP-C-12 `--no-compliance` exists for local trials; such a bundle fails `verify-offline.sh`.
- GAP-C-13 npm build tooling and optional dependencies are in the SBOM with scope `excluded`.
- GAP-C-14 The task page message for other object types now says "change", "MBOM" or "baseline" instead of "part".
