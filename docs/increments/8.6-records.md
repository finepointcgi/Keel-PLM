## Assumptions (FEAT-REC-n)
- FEAT-REC-1: Records kinds are documents and parts. Lifecycle state keys `Released`/`Obsolete` define triggers; an object with a revision still in work or review is never due.
- FEAT-REC-2: Roles: `plm-records` manages and executes, administrators manage but cannot execute, auditors read. The role grants no object access; a records manager also needs the viewer role (and author/org match to start reviews).
- FEAT-REC-3: Disposal keeps identity (number, name, revisions, links, signatures, markings, audit); stored files are released to the vault sweeper. Names are not scrubbed.
- FEAT-REC-4: The first matching class by priority then code decides; a matching class without a trigger date means "not due".
- FEAT-REC-5: Program close and contract end are recorded per program by hand; latest entry counts.
- FEAT-REC-6: A hold only grows until released; program and query holds see all objects; reports to people are filtered; the hold record has no markings.
- FEAT-REC-7: Release of a hold is a signed review by an approver other than the submitter.
- FEAT-REC-8: Dependents: a document linked from a live part, or a part used in a live parent's structure, is skipped ("referenced") unless that dependent is disposed of in the same request.
- FEAT-REC-9: Marked (CUI or export controlled) requests: the requester cannot execute (two-person rule).
- FEAT-REC-10: A request or archive is one program (minimal marking cover, ADR-0019).
- FEAT-REC-11: `review` disposition keeps the object for the class period (12 months when the period is 0).
- FEAT-REC-12: Audit details are identifiers, codes and counts; hold totals are counted in audit, never shown to non-auditors.
- FEAT-REC-13: Archive files are not downloadable from the UI (the marked pipeline lives in Documents); operators extract with `keel-vault verify-archive --extract`.
- FEAT-REC-14: Archives are staged on disk and limited to `MaxArchiveBytes` (2 GiB).
- FEAT-REC-15: The audit extract carries the first checkpoint at or after the last event, if any; without one only per-event hashes verify.
