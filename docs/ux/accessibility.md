# Accessibility and Section 508 conformance notes

Basis: Section 508 (revised, 2017) incorporates WCAG 2.0 A and AA for web content; Keel targets WCAG 2.1 A and AA. Design rules: [design-system.md](design-system.md).
Decision record: [ADR-0034](../adr/0034-accessibility-and-performance-at-scale.md). This is a self-assessment, not a signed VPAT/ACR; a formal report needs a human tester.

## What is tested automatically
`tests/Keel.E2E/AccessibilityTests.cs` runs the vendored axe-core 4.10.2 (tags wcag2a, wcag2aa, wcag21a, wcag21aa, best-practice; no allow-list) in the real browser against
the real host, signed in as a person (alice) and as an administrator (ada):

| Area | States audited |
|---|---|
| Home, all list pages, create forms, search, tasks, workflows, notifications (tabs and preferences), watching, profile, access, TDP, not-found, access-denied | each |
| Part page (11 tabs), where-used, compare versions, compare units, under-review part | each tab and page |
| Document page (7 tabs), change pages (10 tabs; ECR, PR, ECN under review) | each tab |
| Baseline (5 tabs) and compare, MBOM (9 tabs), MBOM compare and side-by-side | each tab |
| Impact map, BOM treemap, structure diff, timelines | picture and table view |
| Admin (all 17 pages), audit | each |
| File viewer (image) | ready state |
| Overlays: command palette with results, user menu, notification bell, confirmation dialog | open |
| 50,000-line structure: grid, purchasing summary, treemap, where-used, part list | `ScaleTests` |

Configurations: light, dark and high-contrast at 1280 px; light and high-contrast at 375 px. The marking banners (top and bottom, identical, non-empty) are asserted on every page.
Rules cover contrast (4.5:1 text, 3:1 large text and components), names and roles, landmarks and regions, table headers, required ARIA children, scrollable regions, duplicate ids,
language, link and button names. Unit tests add: contrast of every token pair in all three themes, one h1 and no skipped heading level, no inline script or style (CSP).

Violations found by the first run and fixed are listed in [increments/7.7-a11y-performance.md](../increments/7.7-a11y-performance.md).

## What remains manual (not provable by a scanner)
- Screen reader walk-through (NVDA/JAWS on Windows, VoiceOver on macOS) of: object page tabs, the BOM treegrid, diagram nodes and their table alternatives, the viewer toolbar, the palette.
- Meaningful reading order and focus order across dialogs, drawer navigation at 375 px, and the focus return after Escape. Keyboard operation is covered by E2E tests for the palette, tabs, tables, grids and diagrams; the whole-product order is a human review.
- Whether names, instructions and error messages make sense (axe checks that they exist). Plain-language review of marking-banner abbreviations for a first-time user.
- Colour meaning in the visuals (patterns and words accompany colour by design; judged by a person with colour-vision deficiency).
- 3D model viewing (WebGL canvas): a canvas has no accessible structure; the file download and the metadata beside it are the alternative. Judge per use case. The Viewer tab of document and part pages (9.5, ADR-0052) adds a complete text alternative (the structure list with positions and boxes), keyboard control (arrow keys, Shift+arrows, + and -, 0/Home) and named buttons, and axe passes on it in all three themes; a screen reader walk-through of the tab (the list as the only view of an assembly, the live status line) stays on this manual list.
- PDF content viewed in pdf.js depends on the tagging of the source PDF; the marked download of a PDF is generated by Keel and is not tagged.
- Zoom to 200 % and 400 % reflow, text spacing overrides, and forced-colours mode in real browsers (only 375 px reflow and the three themes are automated).
- Time limits: the idle lock warns before locking and can be extended; confirm the wording and timing with users who need more time.
- Media: the product has no audio or video.

## Section 508 chapter 5 and 6 mapping (summary)
| Requirement | Status |
|---|---|
| 501.1 / E205 WCAG 2.0 AA | Automated rules pass; manual items above open |
| 502 Interoperability with assistive technology (name, role, value, focus) | Automated; manual screen reader pass open |
| 503 Applications (user preferences: themes, density, reduced motion honoured) | Met by design (`prefers-reduced-motion`, high-contrast theme) |
| 504 Authoring tools | Not applicable |
| 602 / 603 Support documentation, support services | This document and docs/setup.md; support process is the operator's |
| 302 Functional performance criteria | Keyboard-only, low vision (themes, zoom), no-colour-perception (patterns and words) supported; speech and hearing need no special features |
