# ADR-0059: CI pipeline, supply-chain checks, SBOM and the committed licence inventory

Status: Accepted

## Context
Until now the test suites were run by hand (`scripts/test.sh`, `scripts/e2e.sh`) and there was no pipeline file. The browser suite takes about 19 minutes, which is too slow for every pull request. The offline bundle already generated a CycloneDX SBOM (ADR-0033), but the list of third-party licences was only generated at release time, covered the NuGet packages of the three shipped programs, the npm lock file and the vendored viewer files, and said nothing about the Python add-on, the test and tooling dependencies, or what happens when someone adds a dependency and forgets the notices.

## Decision
- **Workflows in `.github/workflows`** for GitHub Actions (the customer's or the vendor's GitHub environment; the application itself makes no external call and nothing here runs on a customer site).
  - `fast.yml` (reusable) is the fast set: build with `-warnaserror`, unit tests, integration tests (Docker, Testcontainers), the OpenAPI drift check, the Markdown link check, secret scan, workflow lint, the licence inventory and policy check, the dependency advisory audit, SBOM generation, and the Helm and compose bundle checks. `pr.yml` runs only this.
  - `e2e.yml` (reusable) is the browser suite with the Playwright Chromium cached by the pinned Playwright version. `main.yml` (push to main) and `nightly.yml` run it whole; `axe.yml` runs only the accessibility class on pull requests that touch `src/Keel.Web` or the axe test.
  - `image.yml` builds the production image from the pinned bases and runs `scripts/verify-compose-example.sh`; `drills.yml` runs the backup and restore drill, the upgrade rehearsal and the load smoke (ADR-0060). Both run on main (image) and nightly.
  - Every action is pinned to a commit SHA (resolved on 2026-10-30; the tag is in a comment), every workflow declares `permissions: contents: read`, every job has a timeout, and no workflow uses `pull_request_target` or `workflow_run`. `scripts/ci/lint-workflows.rb` enforces this (and script injection through `${{ github.event.* }}`, missing scripts, unknown `needs`, undeclared reusable inputs). It is a structural linter written for this repository, **not actionlint**; actionlint was not run because it is not installed and was not downloaded.
- **Checks are scripts, not YAML**, so they run the same locally and in CI: `scripts/ci/check-md-links.py` (relative links, images and anchors; external URLs are never fetched), `scripts/ci/secret-scan.py` (private keys, tokens, JWTs, passwords in connection strings; deliberate development-only credentials are listed with a reason in `.secret-scan-allowlist`, and a stale entry fails), `scripts/ci/dependency-audit.sh` (NuGet `--vulnerable --include-transitive` and `npm audit`; connected machines only), `scripts/update-openapi.sh --check`.
- **SBOM and licences from the real dependency graph.** `src/Keel.SbomTool` (keel-sbom) reads the NuGet restore results of every project, the viewer tool's npm lock file, the vendored files (hashes recomputed from disk), the embedded fonts, the image pins, the Python add-on (`tools/freecad-keel`: its files digest and runtime dependency statement) and a `development` section of `deploy/offline/third-party-sources.json` (the add-on's Python packages, the FreeCAD host, the test-only axe-core). `scripts/generate-sbom.sh --out DIR` writes `sbom/keel-plm.cdx.json` (what is delivered) and `sbom/keel-plm-full.cdx.json` (plus everything used to build and test, scope `excluded`), CycloneDX 1.5, with SHA-256 and SHA-512 hashes where the source has them.
- **`THIRD-PARTY-LICENSES.md` is committed and enforced.** It is generated (`scripts/generate-sbom.sh --licenses`), deterministic, and lists every component with licence and hash. `ThirdPartyLicensesTests` enumerates the dependencies independently of the generator and fails when any has no row, when a row is stale, and when the committed file differs from a fresh generation; a mutation test proves that removing a row (MudBlazor, a npm package, a Python requirement, an image pin) fails the check. `keel-sbom licenses --check` runs the same plus the **licence policy**: every component declares a licence and none is AGPL, SSPL, BUSL, non-commercial or plain GPL; weak copyleft (LGPL, MPL-2.0) passes only where it is already recorded, and a delivered copyleft component needs a pinned source archive (a generator warning that `--strict` turns into a failure).
- **Legal status is untouched.** `docs/review/legal-open-source.md` gets the new facts (counts, the Python add-on, unverified licence ids); its status stays pending counsel review, and the generated documents say so.

## Consequences
- A pull request cannot add a dependency, a vendored file, an image pin or a Python requirement without regenerating `THIRD-PARTY-LICENSES.md`, which puts the new licence in front of the reviewer.
- The Python package licences in the catalogue are entered from upstream statements, not read from installed packages (the repository does not pin them): they are marked in the SBOM as such. Pinning them with hashes is a follow-up if the add-on's dev environment becomes part of a release.
- The workflows were validated structurally and by running every script they call; the workflows themselves were not executed on GitHub. Third-party actions are limited to checkout, setup-dotnet, cache and upload-artifact.
- Image SBOMs (operating-system packages) still depend on `syft` at bundle build time (ADR-0020).
