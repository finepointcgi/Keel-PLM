# ADR-0047: Open-source CAD connector approach

Status: accepted (increment 9.2, 2026-10-29). Builds on ADR-0035 (CAD integration). Assumptions are OSS-CAD-n in [increments/9.2-open-source-cad.md](../increments/9.2-open-source-cad.md).

## Context
ADR-0035 delivered the server protocol and the `keel-cad` tool but no connector for any CAD system, and nothing had been run against real CAD data. Commercial plug-ins (NX, Creo, SolidWorks, CATIA) need licensed SDKs we do not have. We want something real and testable now.

## Decisions
1. **Build the connectors that open-source CAD allows, and make the whole path testable with real files.** A FreeCAD workbench (`tools/freecad-keel`) and recipes for systems that export files (KiCad, CadQuery, OpenSCAD, Onshape/Fusion export-only). Commercial vendors get a developer guide that claims nothing was built.
2. **Logic outside the host.** Everything except the GUI layer is plain Python without a FreeCAD import (settings, token, HTTPS client, work folder, structure extraction over duck-typed objects, payload, validation). It is unit-tested with pytest against a fake server and stand-in objects. The GUI module is thin and is the only file importing FreeCAD and PySide. This is the same rule we give vendor authors (core without vendor assemblies).
3. **Client of the existing API only.** No server change, no new endpoint. Direct HTTPS with the standard library; no dependency on the `keel-cad` binary. The folder state file is `keel-cad`'s own format so both tools can share a folder. Auth reuses the CLI's mechanism (JWT in an environment variable or a mode-600 file, plus an optional token command run without a shell); passwords and tokens are never stored by the add-on. The client refuses plain http to remote hosts and refuses redirects so a token cannot leave the configured host.
4. **Real CAD files as fixtures.** STEP assemblies and parts are generated by Open CASCADE (through CadQuery), committed small (each under 200 KB) with a documented, reproducible script. They test the STEP reader end to end, including the real services (proposal to applied BOM). Bugs they exposed are fixed in the reader and recorded.
5. **Drawings travel as references and associations, not in the BOM.** The structure schema is closed; adding a drawings member would be a server and schema change with no demand. TechDraw pages become check-in references (stale detection) and `drawing-of` associations.
6. **Honest scope.** The FreeCAD GUI layer and FreeCAD object-model assumptions are unverified in a real FreeCAD (not installed, not downloaded). An optional headless script exists and runs only when FreeCAD is present. Cloud CAD (Onshape, Fusion) is export-only because the runtime is air-gapped.

## Consequences
- Keel gets a connector that can be exercised on a developer machine without any CAD licence; the first real FreeCAD run is a pilot with a known list of assumptions.
- The STEP reader now handles raw UTF-8 names, duplicate product ids, explicit count quantities, complex usage instances, edition 3 DATA sections and schema-based protocol detection; placements stay unread (no field in the neutral structure).
- Python tests live in `scripts/test-addons.sh`, outside the .NET suites.

## Alternatives considered
- Wrapping the `keel-cad` binary from FreeCAD: less code, but a second install per workstation and weaker error handling. The CLI remains an option for vendor add-ins (see cad-plugins.md).
- Parsing FCStd files outside FreeCAD to extract the structure: possible (they are zip files of XML) but duplicates FreeCAD's link semantics; rejected.
